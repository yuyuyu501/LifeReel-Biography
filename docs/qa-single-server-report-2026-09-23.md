### 任务和容器故障恢复

- 20 个并发重复提交均返回 202，只生成一个任务，执行次数为 1。
- 实际领取任务后停止续租：重新启动 worker，约 60.81 秒后任务完成。
- 旧租约令牌执行被拒绝，返回 409。
- 强制终止隔离 API 后重启，约 10.69 秒恢复就绪。
- 停止隔离 PostgreSQL 后，API `/ready` 返回 500，能够表示不健康；数据库重启后约 1.04 秒重新就绪，无需重启 API。
- 故障恢复后新的采访工作流正常完成。

测试脚本校正说明：第一次脚本通过 Web 请求 `/ready`，实际落到 SPA 首页，因此得到错误的就绪判断；保留原始记录 `preliminary-results.json`，修正为直接访问 API 后重新执行了恢复测试。第二次原始记录中的 readiness 检查仍显示 false，原因是断言只接受 503，而真实返回 500；这不表示数据库故障未被发现，非 2xx 已满足容器健康检查的失败条件。没有把原始数据改写为通过。

## 4 小时持续运行结果

5 个客户端、每次操作后等待 1 秒，连续运行 14,403.03 秒，包含读取、人物修改、不同内容的 256 KiB 文档上传、异步采访/剧本工作流。共完成 70,853 次请求：70,262 个 200、355 个 201、236 个 202，全部属于成功响应；失败数为 0。操作包括 66,719 次读取、3,543 次修改、355 次上传和 236 次异步任务提交。P50/P95/P99 为 13.09/30.73/57.54 ms，测试期间没有达到资源保护阈值。

451 次资源和公网健康采样全部返回 200；最低可用内存 5,816 MiB，交换分区使用 0，末次磁盘剩余约 60.38 GiB。隔离测试库最终 241 个任务全部 completed；重复业务扣费数为 0，冻结余额为 0。测试结束后仅停止了 `lifereel-singleqa` 容器，生产容器仍健康运行。

隔离 API 容器停止时退出码为 137，但 Docker 标记 `OOMKilled=false`，发生在测试结束的容器停止阶段；测试期间未观察到 OOM 或资源告警。数据库、Web 和 worker 正常退出，生产 API 当前 `/ready` 返回 ready。

故障恢复阶段保留的“Readiness detects database outage”脚本检查为 false，实际响应是 500 而脚本只接受 503；数据库断开时 `/ready` 已返回非 2xx，且数据库恢复后 API 无需重启即可重新就绪。该项按断言缺陷记录，不把它计作产品故障。
