# 4 核服务器并发升级

目标是 100 人在线、10 人活跃，不把该目标当作已通过压测的容量承诺。

## 实施步骤

1. 用已有 PostgreSQL 任务表建立可靠队列，增加任务租约与调度索引。
2. worker 使用独立的采访、视频消费线程，默认并发分别为 3 和 1。
3. 原子领取、定期续租、完成确认；worker 崩溃后可重新领取。
4. API 保持单进程，模型请求最多 4 个并发，CPU 转写和视频拼接各 1 个。
5. 鉴权后的媒体读取重定向到短期 OSS 签名 URL，保留私有 Bucket。
6. 本地自动化测试、隔离数据库并发测试和无付费 AI 的容量检查。
7. 提交 GitHub，服务器备份、迁移、拉取同一提交并部署，验证数据与服务。

## 边界

数据库是任务状态的唯一来源，Redis 保留给原有功能，不再用破坏性 BLPOP 消费生产任务。
租约到期不代表 API 请求已停止，执行锁仍用于防止重复调用。已返回明确失败的任务
不自动重做，保留原有人工重试规则；未知费用仍由钱包待结算机制阻止盲目重试。
所有队列接口只接受 worker 专用凭证，并在公网 Nginx 阻断。
API 单进程使进程内资源上限有效；扩容 API 副本前需换成分布式资源限流。
云模型 RPM/TPM/视频并发配额、OSS 带宽费用仍是独立限制。

同一人物不同章节共用知识图谱，因此采访执行锁按人物隔离；不同人物可以并行。
本地转写与视频关键帧提取改为分块落临时文件，避免 2 GB 视频被重复读入内存。
CPU 转写、抽帧、拼接分别限为 1 个，Whisper 使用 2 个 CPU 线程。
OSS 的短期 URL 可在过期前被持有者使用，不能视为即时可撤销授权；响应禁止缓存，
Bucket 不改为公开。MinIO 的容器内部地址不适合浏览器直读，本地可关闭 MEDIA_DIRECT_READ。
实测 OSS 默认域名拒绝通过签名覆盖 Content-Type，因此签名不覆盖响应头；新上传文件
写入正确 MIME 类型。图片、音频、视频直读，文档保留原站内代理预览，避免 OSS 强制下载
破坏 iframe 预览。文档仍占用应用带宽，应单独观察大文档并发。

## 本地验证记录

- 独立 PostgreSQL 从空库迁移成功。
- 10 个消费者争抢，采访最多 3 个、视频最多 1 个，12 个模拟任务各完成一次。
- 本地 100 并发、300 次人物/章节读取请求全部成功，P95 313 ms。
- 上述测试不调用付费模型，不代表云端 AI 延迟、供应商配额或线上满载容量。
