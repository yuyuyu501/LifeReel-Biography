# Lite 人物访谈

2026-10-12，按 Lite 访谈能力补全计划实现。适用于按人物续填人生资料的采访链路；历史章节采访继续沿用原流程，仅共享模型路由。

## 一轮对话

1. 读取当前账户、人物的资料版本、出处、最近八轮原话与访谈状态。
2. 明确暂停、结束或拒绝时立即响应，保留边界，不调用模型追问。
3. Lite 提取候选资料并选择场景、影响、澄清、换题、暂停或结束动作。
4. 必要时查公开历史资料，再据实际检索结果生成候选。
5. 校验格式、出处编号、问题数量、重复、年份、假称检索及已知错误预设；独立调用审核器检查完整回复和每条资料的语义。
6. 最多重写一次，普通审核始终使用 Lite。格式、审核或主要渠道故障将本轮标记为失败，保留回答和已有资料，不发布未审核的候选。
7. 仅保存审核认可、原话存在且版本有效的条目，记录审核、动作及公开来源后发布回复。
8. 本轮完成后，按需创建持久化后台策略任务，由 Sol 提供后续追问方向。当前回复不等待 Sol；Sol 不直接改资料。

原有资料表的 `reported/confirmed/uncertain/disputed/pending` 状态继续使用。`disputed` 对应计划中的未解决冲突；旧值与新陈述在同条记录的 alternatives 中保留各自出处。它不会进入可写作资料快照或有效记忆。明确更正后形成新有效版本，旧版本可在资料历史中追溯。用户手动确认、更正、删除、使用范围限制仍由原有版本控制维护。

`interview_sessions.interview_state` 保存当前动作、主题、目标、拒谈原话和最新来源。资料提取与审核检查讲述者和传记主角的关系，避免把父母的身份写成本人。来源保存当前回答版本，现有个人执行锁与资料 expected_version 防止过期任务覆盖新版本。

## 配置与回退

```env
LLM_PROVIDER=openai-compatible
INTERVIEW_LLM_BACKEND=volcengine
INTERVIEW_LLM_MODEL=doubao-seed-2-1-lite-260915
INTERVIEW_ENHANCEMENTS_ENABLED=true
INTERVIEW_HISTORY_ENABLED=true
INTERVIEW_REVIEW_ENABLED=true
INTERVIEW_ADVICE_COOLDOWN_TURNS=4
INTERVIEW_REVIEW_LLM_MODEL=gpt-6.1-sol
INTERVIEW_LLM_STREAM=false
INTERVIEW_LLM_THINKING=disabled
INTERVIEW_LLM_READ_TIMEOUT_SECONDS=25
INTERVIEW_REVIEW_LLM_READ_TIMEOUT_SECONDS=60
INTERVIEW_TURN_BUDGET_SECONDS=75
```

采访与普通审核使用现有 `VOLCENGINE_API_BASE_URL/VOLCENGINE_API_KEY`。Sol 后台建议复用 `interview_review` 路由和现有 `OPENAI_COMPATIBLE_BASE_URL/OPENAI_COMPATIBLE_API_KEY`，不改变写书等任务的模型。每次 API 调用保留现有用量账本。`INTERVIEW_REVIEW_ENABLED` 现在控制后台顾问，不再开启同步 Sol 审核。

后台顾问使用现有 database 队列和 interview worker，要求 `INTERVIEW_CONCURRENCY>=2` 和 `LLM_CONCURRENCY>=2`。每次最多一个顾问运行，至少保留一个 worker 名额给普通采访，普通采访优先领取。旧 Redis 队列配置和并发为一时不排顾问任务，主聊仍可独立运行。共用 Model Gateway 的其他任务仍可能占用模型容量，后台化不等于端到端延迟保证。

触发条件为重写/剔除/冲突、同主题至少三轮、记忆卡住或第三轮之后的阶段转换。同一会话只保留一个排队或执行中的建议，默认至少间隔四轮。停止、拒谈不触发建议。任务创建、失败、过期和模型用量可在内部记录追溯，不在用户任务列表显示。

建议绑定会话、资料版本、原回答版本、当前话题和工作流。调用前后均校验；有新提交、手工更正或话题变化则废弃。下一轮仅使用仍匹配的完整建议；建议的出处还须在 Lite 本轮上下文中。建议只是选择方向的输入，回复和新增事实仍经 Lite 独立审核。顾问超时、格式错误和执行中断不影响已完成的采访，也不自动重试付费调用。

事件对象的增量补充在审核前合并，保留未提供的键和已有叙述；字符串仅做逐字规范化去重，不声称解决语义同义重复。新旧内容一起接受独立审核，真实矛盾仍进入待澄清状态。AI 资料的 `source.evidence` 保存多个回答出处，明确更正通过版本历史追溯旧值。时间范围扩展和地点细化不会因字符串不同自动成为冲突；审核器负责判断语义是否互斥。

历史工具的非法请求和查询故障单独记录，不丢弃本轮可审核的个人事实。只有成功来源允许公开背景陈述。“出生地与成长地”合并字段只有成长信息时使用 `growth_place`，不能把长大地点当出生事实；亲属搬家不能填主角搬迁，上学不能补成毕业。更广泛的身份、行为与因果审核仍依赖语义审核。

模型回显存储元数据时移除它们，所有出处由应用建立。漏填的书中称呼仅从明确称呼原话恢复，叙述字段可直接用本轮逐字引用生成候选，其他字段仍要求模型补正。相同状态和使用范围的单值叙述、待续话题可合并为一个候选；引用扩展为覆盖双方的连续原文。所有规范化仍在独立审核之前，不能自动授权保存。

火山采访调用显式传入 `thinking.type=disabled`，避免默认推理耗时超过读取超时；该参数只发给火山采访渠道。模板字段只传必要的名称和类型，审核只传证据，不重复发送完整填表模板。单值字段统一使用 `record_key=single`。用户修改书中称呼属于偏好更新；身份冲突仍需核对双方出处。失败不会生成虚假的成功资料版本，界面区分回答保存与资料整理成功。供应商返回状态不确定时保持调用幂等保护，不自动重复付费请求。

模型误用单值记录 ID 时先规范为 `single`。引用必须是连续原文；仅当分号或句号分隔的每个片段都能按顺序逐字定位时，恢复覆盖它们的原文后再做语义审核，不能用整条回答掩盖缺失证据。年份可来自相邻句，审核仍需核对年份属于哪段经历。诊断记录引用修复下标、程序问题和校验路径，不记录凭据。

审核下标允许规范明确的非负整数字符串，仍拒绝布尔、浮点和越界值。生成的结构错误最多重写一次，与语义重写共用次数和时间预算；通过格式修复后仍须通过事实审核。

审核器附带的未知字段不参与审核决策；只有已定义且校验通过的 verdict、safe_change_indices 和冲突引用能决定保存行为。

精确引用匹配由程序执行，结果传给审核器；模型负责事实含义、经历归属和回复预设，不重复猜测原文字符串是否存在。

审核材料明确标出本轮讲述者原话，允许新增此前未记录的事实；旧资料不包含该事实本身不是拒绝理由。保留完整旧值和引用内容，同时省去重复存储元数据。冲突引用限定为候选同字段的旧记录，非法关联最多重审一次，仍非法则保留回答并标记失败。跨句或省略主语的亲属搬迁结合本轮完整回答和上一轮人物线索检查，不能只看候选截取的一句话。

连续记不清的次数不随话题名称变换而重置。没有新增具体经历时，策略提示换到另一人生阶段，避免在同一时期轮流追问家人、物件等细节；这仍是需要真实访谈验证的推进策略，不保证模型每次都遵循。

审核格式或下标关系不合法时最多重新审核一次，不放行原结果。明确更正下岗、离职、入职、毕业、结婚或搬家的年份时，遗漏的关联记录可生成替换年份的候选；候选仍进入独立审核，不能绕过出处与语义检查直接修改资料。

回复年份校验允许使用近期用户原回答，不将 AI 问题中的预设当证据。一次重写后若追问仍被拒绝，但存在独立审核通过的事实，则保存这些事实并使用固定中性续聊句；审计明确标记 reply_fallback，不计为模型追问质量通过。

候选中的跨轮年份也可来自近期用户原回答，但语义审核必须核对事件归属。模型遗漏 decision 元数据时使用保守 clarify 默认值，再审核完整回复和事实；不自动编出策略、历史请求或用户边界。

重写后仍违反程序证据检查的条目单独剔除，剩余条目和完整回复须再次审核通过后才能保存。全部候选均被剔除时仍为失败；审计记录被剔除的字段和原因，不能把遗漏当作完整提取。

全轮预算用于阻止继续检索或重写，单次请求另外受连接和读取超时限制；不是严格的端到端延迟承诺。审核不向用户流式展示。普通轮通常两次模型调用，含历史查询或一次重写时调用更多，Sol 后台调用另计用量。实际延迟与费用须在真实访谈中测量。

增强人物采访暂不启用供应商直接出声的实时通话，因为该音频无法在播放前审核。文字与录音转写后发送的采访正常使用；历史章节的原实时通话入口不受该人物模式限制。后续语音输出需要接在审核通过之后。

按需开关可单独关闭搜索和 Sol。关闭增强开关恢复原资料提取流程；如同时恢复旧模型，须一并恢复采访渠道和型号。数据库迁移只新增 JSON 字段；已有状态/出处时禁止直接降级丢弃它们，应用回退可保留新增字段。

现有 token 零售计价只支持旧 Character 型号，不能套用到 Lite/Sol。本次沿用原有按成功章节更新计价配置，记录供应商用量但不新增未经核实的 token 价格。

## 历史检索边界

首版支持高考、农村承包、改革、务工、教育、国企改革、洪灾、地震与铁路九类公开线索。请求只允许事件枚举、省份/全国和最多十五年的范围；姓名、私人经历和自由文本不能进入搜索词。只有出生年份不会触发查询。

适配器使用中文 Bing RSS 获取链接，再读取 HTTPS 的政府、高校、人民网或新华网原页面；搜索摘要不当作历史证据。每轮一次查询，最多两条来源，不追随重定向，限制响应大小和等待时间。公开查询按小时缓存，缓存容量有限且不含访谈原文。未找到、不可用、上下文不足和关闭状态分别保存；失败不否定用户回忆，不声称查过。

公开资料是未经人工校订的页面摘录，由审核器核对与回复的关系；来源地区、时间范围是查询条件，不能据此断言页面证明该地区所有人的经历。界面显示来源链接，资料不写入个人经历。地区覆盖和搜索召回仍有实际限制，需要逐步扩展事件工具与来源，不能视为完整地方史数据库。

## 验证范围

自动回归使用合成模型响应和公开页面夹具，检查拒绝边界、完整问句预设、无依据资料过滤、一次重写、渠道故障、更正版本、账户人物隔离和检索真实性。迁移在隔离 PostgreSQL 验证，前端以桌面与手机视图检查空状态和添加人物入口。

这些检查验证流程约束，不证明模型实际对话质量或延迟。2026-10-13 经用户授权在本地隔离数据库进行 Lite/Sol 真实 API 测试，结果和仍未通过的验收项目见 [混合方案实施与验证](reports/2026-10-13-lite-sol-hybrid.md)。模型评测未使用真实用户资料；用户随后另行授权上传 Git、更新服务器并在线上验收前端，发布成功不代表整体访谈质量达标。
