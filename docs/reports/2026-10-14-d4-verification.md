本轮已在本地实现修复，完成两次有限真实调用以及冻结回执离线回放。
能够确认具体应用误判已修复，不能确认增强核查整体优于普通 D4，也未达到整体访谈验收。
默认仍为 baseline；未提交、推送或部署，生产仍为 `2b0a5ed` / `d4-baseline-20261014`。

## 修改

上轮成功保存样本的事实支持率并非低分，主要不足是召回、字段和可靠性。
不能把“少记事实”统一说成 Sol 语义判断错误。本轮分别处理以下路径：

| 路径 | 修改 |
| --- | --- |
| 通用行动错误归类 | 生成schema删除event_action，旧谓词进入待核对；师傅、单位不得自动当亲属 |
| 职责错误关联 | 有可靠谓词和原话的单值字段解除跨字段entry_id，不将工作条目ID写入职责列 |
| 独立记录 | 增强组只给Sol原话与Lite拟回复，不给Lite事实候选 |
| 覆盖与出处 | 逐段原话对应候选；核查主体、行为、必要时间/对象/状态；前因附到持久化证据 |
| 旧事实关系 | 区分新增、重申、细化、更正、冲突，绑定旧原子事实下标和出处 |
| 细化与去重 | 泛称单位加有依据的全名不冲突；两个具名单位仍澄清；重复拒答合并，原话保留 |
| 更正范围 | 增强组定向替换相关原子事实，保留其他事实及内部限制 |
| 输出上限 | 增强Sol为8192，其他结构化请求默认4096；内部RPC同步支持并有载荷回归 |

程序校验只识别部分违反规则的情况。模型说supported、coverage覆盖全部字符都不能证明
语义正确或无漏记。no_fact分类、同义重申和问句前提仍须人工审核。

## 实测后的修复与回放

v1暴露三处可复现的应用误判；修复后仅重用原响应，未重发付费请求：

1. “一家印刷厂”到完整名称未被识别为泛称细化；修复后旧响应不再冲突。
2. event_key含20261014等元数据数字，整条家人记录被当新增年份拒绝；检查改用
   不含event_key的事实载荷，事实年份仍校验。V03旧四事实可正常通过。
3. coverage带逗号，候选引文不带逗号，虽然区间重叠仍失败；改为原文区间有实际文字
   重叠，逐字存在、完整覆盖和关联要求保留。V04第2轮由fallback变pass，菜谱及待续
   进入open_threads。

17对完整Lite/Sol响应完成离线回放，3次缺Sol响应的通道失败跳过。
这是独立回合适配回放，未累计持久化重演全部人物，不当作新真实成绩，原结果保留。

实测后又补普通D4的对象value格式指令、纯年份“1987/1987年”等价处理、家人不同迁居
事件区分、旧事实关联的原消息ID/版本核对。最后补丁有针对性回归，未完成新真实渠道复验。
上轮旧grounding响应缺本轮coverage，回放失败不能当作真实模型退步；其结果单独保留。

## 缺口与发布

失败回答可见但未自动补记；历史可引用不等于表格已写入。V01增强组首轮的实际称呼、
出生、成长和职责就是遗漏实例。普通组对象value句式问题尚需新材料验证。

更正后旧年份可能残留在隐私说明：v1普通组欠债年改成2005，但preferences.exclusions
及use_scope文字仍写2004。内部限制没有放宽，但当前资料不完全一致，不能给该场景
“全部通过”。冲突也仍可将整条复合记录变disputed，相关保留细度需后续处理。

下一阶段应加强可恢复记录任务与事实级版本处理。本轮保留修复和证据，增强核查继续
实验状态，不开启默认，不发布未经验收方案。

证据：`tmp/d4-verification-20261014-v1/`、`v2/`；逐项审核`v2/semantic-review.json`；
