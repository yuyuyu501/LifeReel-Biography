# D4 证据核查与资料检索对照实验

本轮保留线上 `d4-baseline-20261014`，在本地比较原 D4、结构化证据核查、
人物资料检索、两者组合。四组实验代码已经接入，开关默认仍为 `baseline`。
目前固定记录轨的结果支持继续完善检索，但不足以认定组合方案最好或整体访谈达标。

## 方法与边界

基线提交：`2b0a5ed01097670b071aeca6f5666c692070897f`。
采用真实 Lite `doubao-seed-2-1-lite-260915` 主聊和 Sol `gpt-6.1-sol` 完整核验。
Lite 的 thinking 仍为 disabled。本轮“核查”改变 Sol 的提示词和结构输出协议，
没有测试供应商隐藏思考强度，也不要求模型输出思考过程。

| 组别 | D4 完整重建 | 逐项证据支持清单 | 按人物检索 |
| --- | --- | --- | --- |
| baseline | 是 | 否 | 否 |
| reasoning | 是 | 是 | 否 |
| retrieval | 是 | 否 | 是 |
| combined | 是 | 是 | 是 |

检索从当前人物、当前租户的历史回答及有效资料中选择词语相关内容和相邻原话，
保留消息版本、原文偏移、更正状态和使用限制。它是结构化与词语检索增强，
没有使用向量数据库或 embedding；本轮成绩不能作为向量 RAG 的成绩。
检索上限为 1000 条历史、8 个出处、14000 字原话，截断可审计。

固定记录轨为 8 个案例，每组相同材料；隐藏目标事实不送给模型。
长访谈轨计划每组 14 轮，为同一个合成人物许静岚，从新增人物开始，调用实际资料处理和工作流，
每轮通过正常资料 HTTP 接口刷新验证保存。它没有覆盖浏览器交互或完整回答提交路由。
回答控制器按问题关键词选预设回答，并非盲测真人；切题情况须另外审核。
开场及最后四轮边界、更正、结束探针由测试者主动提供，不算模型引导收益。

## 两轮运行

首轮 `v1` 的 32 个固定案例完成，其中 9 个回退：8 个通道连接、读取、连接中断或
HTTP 524，另 1 个为合法结束空回复被结构校验拒绝。首轮长访谈受连接失败影响而中断，
原始请求、失败及已完成回合均保留，没有把中断算作完成。

第二轮 `v2` 将 Sol 连接上限从 4 秒统一调整为 20 秒，读取上限为 240 秒；
Lite 读取上限为 90 秒，回合预算为 300 秒。核查提示明确接收者值只填对象称谓。
四组在同一冻结版本重跑，固定轨最多两个并发调用链路；不自动重试不确定的付费请求。
长轨连续两轮失败则停止该组并记录未完成。两轮不混算成绩。

### 具体观察

- **G01 电话方向：**第二轮核查与组合组正确保留父亲给本人、女儿给母亲及各自时间。
  原 D4 一条接收者写成“讲述者的母亲”，被对象格式规则拒绝，产生不必要的重复确认。
  首轮核查组也因对象值写成长句而漏记；说明输出协议与程序规则同样影响成绩。
- **G02 隐私拒谈：**第二轮四组均记录欠债原因拒答、整段内部使用及作品排除。
  当前原话直接包含欠债话题，足以绑定拒答；冻结来源清单里额外列出的旧 U1
  在这个案例并非必要证据。没有为了补齐来源数量要求模型引用无关旧话。
- **G03 远处原话：**旧 U1 不在最近八条中。原 D4 和仅核查组无法恢复具体电话安排，
  开店天数也因缺少行动者锚点被拦截；检索与组合组找回 U1，准确保留每周开店两天、
  晚上打电话、接收者为母亲。首轮组合组找到旧话但对象值格式错误，仅保留两项。
- **G04 工作职责：**四组均保留入职年份、单位和修书职责。冻结材料把职责字段配对定为
  `work.records[]`，实际四组合理保存到 `work.responsibilities`，因此字段指标每组少一项。
  未看完结果后修改金标准，也不据此要求模型把正确职责硬写到不合适的字段。
- **G05 历史迁居：**成功组没有把女儿 2017 年搬迁推成现在仍住宣城；仅核查组遇到 524。
  原 D4 的当前住址未知记录只保存“她”和“那里”的引文，没有保存其人物与地点前因，
  故该条不计持久化引文充分。完整原消息仍支持其语义事实。
- **G06 停产与离职：**成功组没有推断 2007 年离职或非 2007 年离职；组合组连接中断。
  有些组用 uncertain 表示连续任职未确认，核查组用 unknown，状态一致性仍需改善。
  首轮原 D4 将组织的停产 `event_action` 路由到家人字段，是应用字段映射缺陷。
- **G07 真实歧义：**四组均未把 1943 年归给父亲或叔叔，要求澄清。
- **G08 未上传且结束：**第二轮四组 Sol 均返回合法结束空回复，被 `next_question`
  最少一字规则拒绝，整轮事实未保存。程序显示结束句不算模型及记录成功。
  首轮另出现年份拆到素材说明后被未上传规则拒绝，组合组最终素材说明漏掉 1992 年。

四组都尚未满足现有评定书的全部门槛。retrieval 的本轮召回较高，但字段召回、
首次完成率和结束案例仍未通过；通道失败与单轮波动也不允许据此给模型能力排名。

## 多轮访谈

| 组别 | 尝试回合 | 核验完成 | 是否跑完 14 轮 | 失败原因 |
| --- | ---: | ---: | --- | --- |
| baseline | 14 | 13 | 是 | 首轮 Sol 连接中断 |
| reasoning | 4 | 2 | 否 | 第 3 轮空待核对问句校验失败，第 4 轮 Sol 连接中断 |
| retrieval | 2 | 0 | 否 | 两轮 Sol 连接错误 |
| combined | 14 | 13 | 是 | 首轮 Sol 读取超时 |

仅核查及检索组按冻结的连续失败停止规则结束，未伪装为完整长访谈。
主进程遇到另一隔离进程仍在运行的组合组时，以防重复付费的保护错误退出；
组合组随后在独立进程完成。没有因此重复发送请求或将协调退出算成模型质量错误。

已核对原 D4 的 14 轮：首轮因 Sol 连接中断失败，之后 13 轮核验完成。
第 13 轮把照相馆入职从 1984 年更正到 1985 年，原记录的单位与 1993 年离职仍保留；
两位师傅分别保存在两个教师条目中，没有发生师傅覆盖。
第 11、12 轮保留欠债内部使用范围，未追问原因，但同一拒答产生两条近义原子事实。
师傅行动额外进入家人字段也是明确的归类错误。首轮失败后称呼、出生与成长事实
没有作为有效资料自动补记，不能用后续对话能提到这些信息来宣称表格完整。

回答控制器存在切题缺陷：原 D4 第 5 轮问梁师傅教冲洗的事件，却因“手艺”关键词
选择了转行学修表的回答；第 9、10 轮也没有直接回答具体问题。
因此这些回合的新增披露不能直接当作模型成功引导；本轨以持久化与边界观察为主，
不据此计算完整访谈总分或认证联想收益达标。

仅核查组开场成功后，把“照相馆”补充为“江城照相馆”触发了工作单位的互斥值规则，
正常补充被标成争议；另一条冲洗职责候选误链接到工作经历条目，被字段链接规则拦截。
这不是通过延长思考时间即可消除的程序问题。原 D4 与组合组首轮通道失败，
反而没有保存泛称照相馆，因此没有在同一位置触发该问题；不能据此推断核查组更弱。

组合组第 5 轮承接冲洗温度，得到“水温弄高、师傅要求重做、此后先量水温”的叙述，
第 8 轮能把修表习惯连接到其他工作或日常。问题表达中没有补入创业失败等个人事实。
第 11、12 轮继续保留欠债内部使用限制，但也重复记录拒答；第 13 轮更正年份成功，
两位师傅及离职年份保留，第 14 轮结束且没有生成上传资产。
照片冲洗师傅仍额外进入家人字段；当前做事习惯还被归入工作经历。
这些是有用的局部观察，不能证明各项访谈、联想和持续记忆都达到 4/5。

四组长轨没有组成完整、有效且同条件的访谈能力对照。未知回答后的换题、资料刷新、
更正及隐私有部分证据；暂停、全部 67 字段、公共历史检索及完整联想收益均未认证。
没有生成 85/100 的验收总分，也没有以未测项或程序回退补足成绩。

## 协议修复与离线回放

所有真实运行结束前，七个冻结文件摘要均未变化。之后将应用 D4 方法版本更新为
`d4-profile-20261014-v2`，仅修复以下已复现的协议边界：

1. 用户原话明确暂停或结束，且模型回复为空字符串时，程序补上对应结束句。
   事实、出处及对象仍经过完整校验；仅模型自行声称 close 不足以触发这个默认值。
   审计标注程序补充，不能算成模型引导成功。
2. 待核对项允许没有立即追问的问句。程序只选择有非空问句的待核对项，
   保留没有立即追问的事项及模型正常转题，避免记不清后重复追问或整轮回退。

原始五个模型响应在禁止外部网络的离线回放中，从校验回退转为处理完成：
四个 G08 结束案例和仅核查组长访谈第 3 轮。没有新增真实 API 调用。
原始成绩和失败保留，回放不替换固定轨分数，不算最终版本已完成真实复验。

回放的四组均保留 1992 年纸质全家福未上传，但仍有重复事实、素材说明被拒的问题。
组合组还把“持有纸质全家福”放进 `work.records[]`，是明确的路由错误。
因此“回放处理完成”也不等于完整记录合格。结果单独保存在
`tmp/d4-grounding-retrieval-20261014/replay-control-protocol-v1/`。

## 用量与等待

第二轮固定轨 64 次调用，长轨 68 次调用，共有 132 个请求和响应回执。
其中 7 个供应商传输失败，125 个响应有 usage，已报告 token 合计 1,854,749。
失败调用的消耗未知，不能把该合计当作最终账单；没有推算人民币成本。
未观察到 `finish_reason=length`。

长轨 Sol 调用 P50：原 D4 38.93 秒，组合组 67.45 秒；最长分别为 107.61、240.39 秒，
包含失败等待。这里只是供应商调用计时，未单独测量包含整个 HTTP 提交、资料读取及
数据库保存的端到端耗时。速度继续作为观察项，未降低准确度或完成率门槛。

## 后续顺序

本轮支持先保留可溯源检索作为候选，继续修字段契约、记录对象与错误恢复；
没有足够证据直接启用全部结构化核查。具体下一轮应先处理：

1. 组织、师傅与一般行动不再默认路由到家人或工作经历，明确候选到字段的契约。
2. 区分同一事件的泛称细化、真正冲突与明确更正，避免正常补充变成争议。
3. 同一事件的拒答及重申去重；失败回答有可见待恢复状态，不能悄悄消失。
4. 修正回答控制器的切题问题，冻结完整目标配对，在稳定通道下完成四组长轨，
   再使用未参与修复的新人物验收。

只有词语检索在明确的同义、指代案例中持续漏检时，才增加 embedding 与混合检索对照。
当前服务器能承载这类轻量数据库检索，是否满足具体向量模型和并发量仍须实测。

## 本地验证与发布

新增证据清单覆盖、无效引用拒绝、跨消息必要出处、原文偏移、人物与租户隔离、
回答版本、更正状态、隐私保留及四种协议切换回归。全量后端回归为
970 passed、29 skipped、6 warnings，约 1106 秒；跳过项不计为通过。
协议修复后相关回归 129 项通过，修改及新增 Python 文件 Ruff 检查通过。
此前全量成绩和该窄回归有重叠，不相加为独立总数。

原始请求、响应、使用量、冻结摘要和逐项审核位于忽略目录
`tmp/d4-grounding-retrieval-20261014/v1/`、`v2/`。请求回执不含认证头。
第二轮七个冻结源码另存为 `v2/frozen-runtime.zip`，归档内容与实测前摘要逐项一致，
可区分真实运行版本与之后的协议补丁。
未推送或部署实验方案；生产 D4 基线保持可回退。

服务器只读观察为 8 vCPU、14.96 GiB 内存、约 12.95 GiB 可用内存、
约 62.02 GiB 空闲磁盘，无计算 GPU。PostgreSQL 有 pgvector 0.8.6 扩展文件，
应用数据库尚未启用。当前轻量检索不新增服务；硬件观察不等同于并发容量验证。
