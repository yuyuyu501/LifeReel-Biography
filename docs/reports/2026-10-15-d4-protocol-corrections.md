# D4 协议误拦与关联更正

按本轮决定，优先修复可复现的协议与写入逻辑缺陷。失败后的自动补记、通道稳定性、
调整增强核查调用范围不列入本轮。原有真实实验报告保留，不改写历史成绩。
开发验证阶段仅本地验证，尚未提交、推送、部署；默认仍为 baseline。
后续经用户授权的发布安排见[部署说明](../deployment.md#d4-协议修复发布2026-10-15)，
实际部署结果以该次服务器验证回执为准，以下实验记录保留原状。

## 参考案例与取舍

- [Trustcall](https://github.com/hinthornw/trustcall)：官方 README 的 Updating schemas
  演示整份 JSON 重建会遗漏旧信息，采用 JSON Patch 定向更新已有对象。
  本项目借鉴“只修改已定位事实、保留其他内容”，没有引入整个框架或自动模型重试。
- [Pydantic validators](https://docs.pydantic.dev/latest/concepts/validators/)：允许先规范化
  输入，再执行约束校验。规范化并不证明语义正确，仍须校验出处、对象与事实状态。

这是对现有 D4 原子事实、事件标识、出处和资料版本机制的局部修复，不替换架构。
模型仍为 Lite 与 Sol；未新增付费调用、向量数据库或恢复任务。

## 实际修改

1. 对象格式规范化：`host/call_recipient` 的 value 如为能确定对象的简单肯定关系句，
   本轮逐字引文也明确支持该关系，则先转换为固定对象称谓，再执行原校验。
   已复现的“住在讲述者的弟弟家”可存为“弟弟”，引文完整保留。
   单凭 object_entity_id 不授权转换；未知、否定、问句、备选对象、额外断言不强制简化。
   历史肯定引文不能授权修复本轮的否定陈述。
2. 关联更正：从已通过程序检查的日期更正定位旧条目、主体、事件及原子日期。
   对同主体同事件的 `use_scope/preferences_exclusions` 同步旧年份引用，重建显示摘要。
   只处理年份引用能唯一确定的限制说明，不全文替换所有同年经历。
   其他人物、其他事件、其他年份、拒答状态、内部使用限制和原始出处均保留。
   event_key 是稳定标识，即使包含旧年份也不改写；不能把它当成事实年份。
3. 核查指令一致性：删除一处“否定关系用 event_action”的遗留要求。
   该谓词已被协议禁止，应使用 present_relationships 等具体谓词保留否定范围。
4. 审计索引：其他候选被程序移除后，关联更正的索引同步到最终写入清单。

## 本地验证

最终相关回归90项通过，0失败、0错误、0跳过；修改的 Python 文件 Ruff 和
`git diff --check` 通过。独立旧回执回放共25个完整回合，另5个缺少 Sol 响应而跳过。
本轮没有重新请求真实模型。

- 测试：`tmp/d4-protocol-20261015-final-2.xml`。
- 旧 v1 回放：`tmp/d4-protocol-20261015-v1-verified/result.json`。
- 旧 v2 回放：`tmp/d4-protocol-20261015-v2-verified/result.json`。

回归覆盖 baseline/combined 两种路径的实际持久化与资料 API 刷新，也覆盖否定、未知、
不同对象、不同事件、无依据年份、未确认冲突、旧版手工值和审计索引。

旧 v2 的 V03 第1轮：普通组住所提供者候选不再因完整句格式被丢弃。
旧 v1 的 V04 第3轮：普通组欠债日期、内部说明、不写进书的说明均为2005年，
原因仍未披露，使用范围仍为 internal，原话仍记录当时所说的2004年。

回放是冻结原始输入的独立回合适配，不是累计全人物重演，也不是新访谈成绩。
v1 有17对完整响应可回放，3次无 Sol 响应跳过；v2 有8对，2次跳过。
程序 pass 不代表全部候选保存或语义全对，不重算原来的召回率或整体验收分。

## 保留的限制

含频率、否定方向或多个断言的复杂电话句仍可能被拒绝，不能只取对象称谓而丢掉语义。
事件归属不清、多年份说明、旧版无结构关联资料不自动传播更正，可手改或后续对话确认。
整条复合记录的冲突粒度、全部字段覆盖和新人物主动访谈验收仍未完成。
本轮不以这些残余问题无限扩大修改范围，也不据此声称整体访谈已验收通过。
