# 写书与采访模型池

## 路由与质量边界

主聊、写书及共用 script 任务的首选为 CCTQ `gpt-6.1-sol`，备用依次为火山
`doubao-seed-2-1-pro-260915`、`doubao-seed-2-1-lite-260915`。
采访核查只配置 Sol、Pro；配置中出现 Lite 时拒绝启用核查池。
未配置池的任务继续使用原有单模型行为，memory、vision、video_plan 不随此次修改切换。

模型池在 model-gateway 中执行，本地模式使用同一实现。客户端收到实际成功模型、平台、
回退标记及不含正文的尝试摘要。书稿与视频剧本保存实际生成模型，D4 采访审计保存实际主聊和
核查模型。回退只提高供应商可用性，不意味着整体访谈或书稿质量评测已通过。

允许回退的异常包括网络错误、超时、不完整流、HTTP 200 内的普通上游 error、无法解析的
JSON、404、408、429、5xx，以及明确不支持 response_format 的 400。
通用 400、401、403、409、413、422、明确政策拒绝、余额和计费错误立即停止。
资料不足、字数、事实来源、对象绑定、冲突和引用校验继续由应用判断，不通过切换模型
强行获得“合格”结果。JSON 已解析但不符合业务协议时仍走原有校验或有界修复。

## 尝试限制与故障冷却

每次逻辑模型调用最多尝试三个不同候选，不对同一模型自动反复重发；核查池最多两个。
写书原有一次格式修复是另一逻辑调用，因此最坏情况不是整项写书任务仅三次上游请求。
所有尝试失败后返回错误，保留原业务重试入口。

默认每候选 HTTP 阶段超时上限 180 秒，流式读取另受 180 秒墙钟预算约束；总选择预算
600 秒，采访相关调用收紧至当前采访预算减 10 秒，预算耗尽后不发起后续候选。
HTTP 的阶段超时不是整个任务的绝对执行期限，资源排队及原有校验另计。
相关配置为 `LLM_MODEL_POOL_MAX_ATTEMPTS`、`LLM_MODEL_POOL_ATTEMPT_SECONDS` 和
`LLM_MODEL_POOL_TOTAL_SECONDS`。

同一平台、模型、端点与凭据作用域连续出现两次可回退异常后，暂停该候选 60 秒。
冷却后只允许一个探测调用，成功即恢复；其他请求继续选择后备模型。状态在网关进程内
保存，进程重启会清空，多副本网关不共享冷却。阈值和冷却可分别通过
`LLM_MODEL_POOL_FAILURE_THRESHOLD`、`LLM_MODEL_POOL_COOLDOWN_SECONDS` 调整。

## 计费与重放

每个真实请求独立保存实际模型、成功/失败、耗时、上游 request ID 和原始 usage。
失败且无 usage 的调用不能被推定为供应商费用为零。未添加或猜测新模型的 token 单价；
token 计费模式下遇到未定价模型仍停止，生产继续按成功章节更新结算业务费用。

业务任务仍只冻结、发布及结算一次。完成的网关调用缓存整个成功结果，内部重放直接取
缓存，避免再次调用主模型及备用模型。摘要包括已配置池的端点和凭据哈希作用域，日志
不输出密钥、家庭资料或模型正文。

若较早候选已开始生成或状态不确定，最后候选即使返回 429 等明确拒绝，也保留整次调用
的不确定状态；不能删除幂等记录后重新付费调用。常规模拟测试同时覆盖重放与只发布、
结算一次的书稿流程。
