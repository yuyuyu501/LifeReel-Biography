# 人生资料、书稿与影像改造实施记录

日期：2026-10-08。发布准备记录：三个阶段、本地隔离验收与 Docker 联调已完成。生产提交、迁移、实际镜像及备份以同提交的 deployment-results.json 为准，不能仅凭本文判断运行版本。

## 已实施流程

选择人物 → 多次采访与手动填写人生资料 → 独立目录、约 1000 字书稿 → 保存稿改编剧本/分镜 → 用户另行生成影像。
新采访不再要求选择人生章节，不自动生成剧本，不产生相应剧本生成冻结或扣费；文本模型实际用量仍适用已有规则。
书籍保留章节，一位人物一本书；影像可以选一个或多个当前保存稿，30/45/60 秒，按分镜制作。

批准依据：`docs/plans/2026-10-08-life-interview-book-video.md` 与 `docs/plans/2026-10-08-life-profile-template.md`。

## 资料与采访

- 12 类、67 字段，稳定经历 ID、证据、用途/化名、确定性、资料版本、变更历史。
- 未知、跳过、拒答和不适用计入已处理情况，但不会被算成写书素材。
- 可按主题选择范围；丰富局部经历可写，其他阶段保留缺项，不要求把所有人生类别填满。
- 人工修改与 AI 更新共用版本保护和幂等请求。并发冲突返回 409，Web 保留未保存草稿。
- 第二轮明确纠错修正原经历；记忆投影失效旧事实及时间线，并关闭旧冲突。
- 原先的采访/记忆事实可幂等迁入，旧问答、书稿、剧本和媒体记录继续保留。
- 资料与同步事件同事务保存；记忆服务不可用时资料仍持久化，Tasks 后续补偿，不回落单体执行。
- 文字、转写和实时语音代码都接入资料整理；真实实时语音尚未人工验收。
- XLSX 五个工作表及 Markdown 导出，默认排除内部资料；文本单元格不执行公式。

## 写书与影像

- 书章拥有自有标题、顺序和选材。移出目录后保留历史稿件，可恢复。
- AI 正文有效字符范围 900–1100；短的人工稿可以保存，不用填充文字强凑字数。
- 来源快照绑定当前条目版本。无关条目更新不使全部书章过期；相关来源更正、删除或限制使用会失效。
- 人工核对旧稿后，可明确确认当前资料版本，保存新版本；旧稿不被覆盖。
- 有人生资料的旧采访书籍，先通过目录选材确认当前资料，再继续生成/改编/导出。
- 模型成稿验证来源 ID、字数、重复段落，并拦截没有现行来源的具体年份及特定性别/年龄描述。原始误述不能授权旧年份回到正文。这些规则不等同于完整语义质量保证。
- 剧本采用规划 → 场景/镜头生成两步，checkpoint 保留模型结果，重试复用已完成步骤。
- 多场景剧本追溯到书稿版本；镜头 4–10 秒，继承不露脸等要求。成片视觉忠实性仍需真实模型人工验收。
- 用户撤回来源使用后，不允许新改编、影像/发布或导出；保留已有历史作品供追溯。
- Web 导航为家人、采访、写书、影像；微信/抖音小程序入口和共享契约同步；旧剧本入口转至影像。

## 数据与发布结构

仍用一个 PostgreSQL、九个服务 Schema、三个 Worker。0044 增加三张资料表及来源字段，业务表共 52 张。
media 中仍是标识、OSS key、媒体元数据与分析文本，图片/音频/视频本体继续存放在原存储后端。
新流程数据存在时，迁移拒绝破坏性 downgrade。发布前须备份全库/环境和保留旧镜像，优先向前修复。
后端镜像用固定版本、校验 hash 的 requirements.lock 安装，与 uv.lock 保持一致。

- 写书 Worker 通过内部合成 HTTP 模型端点产出 911 个有效字符，并持久保存，再编辑成第 2 版书稿；未调用真实模型。
- 完整联调 8 项通过：登录/独立服务、Tasks 重启投递、第二轮年份/地点纠错且无猜测性别、Memory 中断后的已提交资料和 durable outbox 恢复、写书 Worker、书稿到两场景剧本及模拟影像、限制来源、读取并发。

- 镜像中 181 个后端源码文件摘要与本地一致；最终 `alembic check` 无新迁移操作。
- Web 浏览器 7 项实际操作通过：登录、聊天填表、结构化手编、历史/表格下载、目录/正文保存、书稿选择/分镜预览、刷新持久化。未捕获的页面异常为 0。

## 整合验收发现并修复的边界

1. Book 创建先 INSERT 再 RPC 读取人物资料，与 Interview 的人物 FOR UPDATE 发生外键锁等待。改为 RPC 在 INSERT 前完成；已有资料直接读取，不申请人物强行锁。
2. 已成功资料请求重放仍持有资料行锁，再 RPC 到 Memory 导致锁等待。验明幂等请求后先提交释放锁，再同步。独立 PostgreSQL 连接在 500ms lock_timeout 下覆盖了书籍创建和资料重放。
3. 书稿只验字数/引用不能阻止旧年份回到正文。增加现行事实验证，兼容历史 claim_text 与新 text 格式，不用原始误述授权旧值。

原始失败证据保留在 tmp。另有测试配置问题：图片恢复 provider 枚举、迁移 fixture 字段、教程旧版本标记、条目与资料全局版本断言，以及合成端点未填模型名；它们不作为产品故障或通过结果混报。

## 生产结果的核验

发布顺序仍为本地测试 → commit/push → 服务器确认干净并获取同一提交 → 活动工作检查与备份/旧镜像保留 → 迁移/服务更新 → 实际运行源码、健康与三方 Git 校验。
生产过程不会生成用户作品或调用付费供应商。数据库备份包含全部 Schema，并对原人物、问答、书稿、媒体与账本记录的行数及摘要作迁移前后比较。
实际部署结果由发布脚本保存并下载到 `tmp/life-profile-qa/server-deployment-results.json`；最终线程回复记录其提交与备份路径。

## 未覆盖范围

1. 真实实时语音模型、真实麦克风录音及平台真机的通话/录音行为。
2. 真实模型的文学质量、是否完全忠实于事实，以及生成画面的不露脸与人物一致性；模拟模型只能验证协议、流程和规则。
3. 微信/抖音开发工具与真机、平台提审发布、平台登录配置及真实支付；不属于本轮模拟发布验收。
4. 独立节点/异地灾备、真实供应商限流、付费 OSS 端到端和本轮长时间稳定性测试。短时单机模拟测试不能据此给出长期或付费模型容量承诺。

## 三个定时检查的执行规则

本轮完整发布验收后，按北京时间每日 09:00、14:00、20:00 创建三个跟进任务。
每次对照两份完整批准计划，分别重点检查资料采访、写书来源、剧本/分镜/跨端。
发现可复现偏差后修改本地、用隔离数据库和模拟供应商验证，并按 AGENTS.md 提交/推送/服务器获取/部署。
不能通过修改计划、删除有效测试或关闭检查来掩盖偏差。
同一 checkout 使用进程级排他锁；未知本地或服务器修改不覆盖。无变化保持安静，修复、失败或需要用户处理时通知。
不得擅自调用付费 AI、短信、支付或真实视频，也不自动覆盖环境密钥、用户资料或个人媒体。
