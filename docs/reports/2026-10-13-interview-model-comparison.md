# Lite 与 GPT-6.1-Sol 访谈对照评测

日期：2026-10-13。状态：本地评测，不发布。评定依据为测试前冻结的
[人生访谈与记录评定书](../interview-acceptance.md)。

## 当前结论

当前应用加两条 API 渠道均未达到验收标准。Sol 在已成功的回复中通常有更好的
故事推进与人物归属，但当前 CCTQ 渠道加生成、审核和保存流程的延迟、失败率
不适合作为默认实时访谈。Lite 速度更好，仍存在人物经历串写和无依据补全，不能
因为速度达标而验收。更换模型不能修复共用的存储、冲突判定和失败处理问题。

## 测试条件

- 本地应用版本：`a809336c6ee721ee56b321d1db2e49276ee2d18b`，应用源代码未修改。
- Lite：`doubao-seed-2-1-lite-260915`，火山引擎；Sol：`gpt-6.1-sol`，现有 CCTQ 渠道。
- 每个模型、每条测试轨使用独立新 SQLite 数据库；正常新增家人 API 只给称呼，资料表为空。
- 同一虚构人物林秀兰；记录轨 30 轮、136 个事实与字段配对、逐项查看 67 个字段。
- 引导轨每模型 12 轮，同一句开场；按实际问题回答隐藏人设，未知内容如实说记不清。
- A08 同一工作线索、A11 同一债务隐私拒绝、A12 同一结束指令；控制输入不计引导成绩。
- 生成和审核都使用被测模型，关闭跨模型升级。温度 0.4，非流式。
- 先测生产常用量级的 25 秒读取超时，再以双方相同的 90 秒读取超时、120 秒
  重写准入预算做补充容量测试。120 秒不是整轮强制截止，不能保证整轮在 120 秒内结束。
- 公共历史工具给双方相同的 `no_results`。真实检索曾无结果；成功检索质量未测。
- 其余付费服务关闭或使用 mock；凭据仅从本地环境读取，不进入报告。

成绩代表“模型、渠道与当前应用链路”的组合，不能视为裸模型能力排名。只有一个合成
人物、一次补充对照，评分由 Codex 审阅，未进行盲评或真实用户研究。
本轮通过本地 TestClient 执行正常 API 和实际编排、保存逻辑，未进行浏览器界面操作；
SQLite 隔离测试也不能替代 PostgreSQL、语音转写和真实老年用户的后续验收。

## 共用流程问题与修复顺序

1. 人物归属和证据范围：保存与追问都须保持明确人物主语；“长大”不能自动成为
   “出生”，孩子出生不能自动成为本人亲自生育养育。新增事实须有独立对话依据。
2. 冲突判定：`profile_extraction.py` 对 `time_raw` / `place` 的不同字符串直接标记冲突，
   R07 双方均被错误打断。时间范围扩展、补充描述和真正矛盾需要区别。
3. 记忆保留：`retain_narrative_context` 使用整串包含判断；累计摘要换措辞后会拼接旧文，
   造成重复。应保存可追溯的事实增量，复用已有事件，确保更新不丢旧事实。
4. 历史工具契约：模型输出的地方粒度与工具枚举不一致时应给出明确可修复校验；
   工具失败不能让用户已经讲出的亲历整轮丢失。
5. 失败隔离：把可靠事实保存与问题改写、公共背景检索解耦；审核拒绝与超时必须可见、
   可恢复，不把“这段已记好”当作保存成功。
6. 访谈推进：限制同一细节重复追问；用户记不清后切换线索；事件已有经过时询问影响、
   选择或后续生活。程序固定澄清句不能算模型的联想成果。
7. 延迟：缩小重复传入的资料和历史内容，分别记录生成、审核、保存耗时；核查 Sol
   中转渠道。在相同代码版本重测双方，随后加入未参与修复的新人物再验收。

这些是下一轮待验证的修复任务，本次没有把尚未实施的优化写成已经生效。
