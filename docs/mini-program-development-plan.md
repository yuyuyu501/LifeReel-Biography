# 微信小程序与抖音小程序开发计划

## 1. 文档目的

本计划用于在现有 Web 端之外，新增微信小程序端和抖音小程序端。后续需求拆分、代码实现、测试和部署都以本文件为基准；如果产品范围或平台能力发生变化，先修改本文件，再修改代码。

当前项目的后端 API、数据库、任务队列、AI 工作流和 OSS 继续作为统一业务后端。Web 端保持现有实现，小程序端作为新的客户端接入。

## 0. 当前实现状态（2026-09-24）

已完成代码：平台身份与可轮换小程序会话、微信/抖音统一登录接口、Taro 双平台工程、Token 自动刷新、首页人物和章节入口、文字采访、普通录音上传、记忆/时间线/冲突展示、剧本与分镜展示、视频任务创建和历史查看。微信和抖音构建均已在本地通过，API 小程序认证测试和现有 Web/API 回归也已通过。

仍需外部配置或人工完成：微信和抖音 AppID、服务器域名白名单、隐私协议、开发者工具配置、真实账号登录、真机录音上传、真实媒体播放和平台审核。实时语音、支付和真实视频/AI 调用继续按本计划排除在本期自动化发布验证之外。

## 2. 已确认的范围

### 首期必须实现

- 微信小程序登录、会话续期和退出登录。
- 抖音小程序登录、会话续期和退出登录。
- 用户与现有租户、人物资料的绑定。
- 项目/人物列表和详情。
- 章节列表、章节状态和章节详情。
- 采访会话创建、继续采访、文字回答和普通录音上传。
- 采访过程中的文本流式结果或轮询结果展示。
- 记忆、知识、时间线和冲突状态展示。
- 剧本、剧情、分镜、对话、场景和视觉约束展示。
- 视频生成任务创建、进度查看、成片播放和历史任务查看。
- 图片、音频、视频和文档的选择、上传、进度展示和失败重试。
- 微信和抖音真机测试、审核配置和生产发布。

### 暂不纳入首期

- 实时语音通话。现有实时语音使用豆包端到端实时语音模型，先保留 Web 端能力，由用户手动测试；小程序端不在本期接入。
- 二维码收款、微信支付和抖音支付。支付接口可以预留，但不阻塞核心功能开发。
- 手机浏览器/PWA 独立版本。
- 多服务器、高可用和独立 CDN 改造。

### 现有能力约束

- 继续使用当前一台 4 核 8 GB 服务器作为部署标准。
- 不把小程序端的上传和轮询设计成高内存长连接服务。
- AI 生成继续由后端 worker 异步执行，小程序只提交任务并查看状态。
- 不在代码库提交 AppSecret、平台密钥、OSS 密钥、支付密钥或环境文件。

## 3. 技术方案

### 客户端技术选型

采用 **Taro + React + TypeScript** 建立小程序客户端，一套业务代码分别编译为微信小程序和抖音小程序。选择 Taro 是因为现有 Web 前端使用 React，领域模型、表单校验、状态模型和 API 类型可以共享。

小程序页面和组件需要按小程序运行时重新实现。现有 Web 页面不能直接打包使用，因为小程序没有完整的 DOM、浏览器文件系统、浏览器 Cookie、`MediaRecorder` 和任意浏览器 Web API。

建议目录结构如下，具体目录名以现有工程实际结构为准：

```text
apps/
  web/                    # 现有 Web 端
  mini-program/           # Taro 小程序端
packages/
  client-core/            # API 类型、请求封装、鉴权、缓存、任务状态
  domain-types/           # 可由后端 OpenAPI 或手工维护的共享类型
```

如果当前仓库不适合立即引入 monorepo，则先在 `apps/mini-program/src/shared` 内实现共享层，等 API 和页面稳定后再抽取公共包，避免为了目录结构提前重构 Web 端。

### 后端身份体系

新增平台身份表或等价模型，用于把平台账号映射到现有用户和租户：

```text
platform_identities
- id
- user_id
- tenant_id
- platform: wechat | douyin
- app_id
- open_id
- union_id nullable
- created_at
- updated_at
```

约束：

- 同一 `platform + app_id + open_id` 只能绑定一个用户。
- 不把微信 openid 和抖音 openid 当作同一个全局用户标识。
- AppSecret 只存服务器环境变量或密钥管理系统，小程序端不能获得。
- 登录后继续签发项目已有的会话 Token/Cookie 体系，业务接口不按平台复制一套。
- 已有 Web 账号如果能提供绑定入口，允许绑定小程序身份；没有绑定时按产品规则创建或邀请到租户。
- 登录、绑定、解绑、刷新会话和失败原因写入审计日志，但不记录 AppSecret 和完整平台凭证。

新增接口建议：

```text
POST /v1/auth/mini-program/wechat/login
POST /v1/auth/mini-program/douyin/login
POST /v1/auth/mini-program/refresh
POST /v1/auth/mini-program/link
DELETE /v1/auth/mini-program/identities/{id}
GET /v1/auth/mini-program/me
```

后端通过微信和抖音官方服务端接口完成 `code` 换取平台身份，客户端只上传短期登录 code，不上传 AppSecret。

### 客户端 API 和状态层

共享客户端层负责：

- API base URL 和平台请求头。
- Token 保存、刷新、失效和重新登录。
- 统一错误码转换为小程序可读的提示。
- 任务状态轮询、退避、超时和页面离开后的恢复。
- 文件上传进度、取消、重试和幂等键。
- SSE 不可用时使用轮询；普通请求仍复用现有 API。
- 音频、视频和图片的临时路径管理，不把临时路径当作永久 OSS 地址。

小程序页面不直接处理 AI provider、worker、OSS Secret 或数据库状态转换，只消费后端返回的业务状态。

## 4. 首期页面和用户流程

### 登录和首页

1. 用户打开小程序。
2. 小程序调用平台登录接口取得临时 code。
3. 后端换取平台身份并创建或恢复项目会话。
4. 首页展示当前租户的人物、章节和最近任务。
5. Token 失效时自动刷新；刷新失败才回到登录页。

### 人物和章节

- 创建、编辑、查看人物资料。
- 显示必填字段校验，显式 null 在客户端拦截，后端继续返回 422。
- 查看章节进度、更新时间、同步状态和未处理冲突。
- 展示记忆、知识和时间线时标识来源和状态。

### 采访和普通录音

- 创建采访会话并显示当前问题。
- 支持文字回答。
- 使用微信 `RecorderManager` 和抖音对应录音 API 录制普通音频。
- 录音结束后先上传到后端，再创建或提交采访 turn。
- 显示上传、转写、知识更新和剧本更新状态。
- 页面退出后可恢复未完成任务。
- 首期不建立实时语音 WebSocket 通话链路。

### 剧本和视频

- 按章节显示剧情、分镜、对话、场景和视觉约束。
- 分镜显示不露脸、人物、时间、地点、镜头类型等约束。
- 视频任务显示排队、生成、合成、完成和失败状态。
- 使用小程序视频组件播放可访问的媒体地址。
- 媒体地址继续由后端生成短期签名 URL 或受控代理地址，客户端不接触 OSS 密钥。

## 5. 平台适配要求

### 微信小程序

- 配置合法 request、upload、download、socket 和业务域名。
- 接入 `wx.login`、`wx.request`、`wx.uploadFile`、`wx.getRecorderManager` 和视频组件。
- 完成隐私保护指引、用户授权说明、用户信息最小化采集和注销/解绑入口。
- 使用微信开发者工具和至少一台真实设备验证上传、录音、视频播放和后台恢复。

### 抖音小程序

- 配置抖音小程序合法域名、上传域名、下载域名和 WebSocket 域名。
- 接入 `tt.login`、`tt.request`、`tt.uploadFile`、抖音录音接口和视频组件。
- 对平台审核要求、隐私协议、用户授权和内容安全提示分别配置。
- 使用抖音开发者工具和至少一台真实设备验证同一套核心流程。

### 平台差异原则

- 平台调用全部集中在 adapter 中，例如 `platform/wechat.ts`、`platform/douyin.ts`。
- 业务页面不出现大量 `if (wechat)`/`if (douyin)` 分支。
- 文件类型、最大大小、录音格式、临时文件有效期和视频自动播放规则以平台能力探测结果为准。
- 如果某个平台不支持某项能力，页面显示明确的替代操作，例如改用文字回答或选择已有音频。

## 6. 后端改造顺序

### 阶段 A：接口和身份基础

- 盘点现有 Web 登录、租户、用户和权限模型。
- 设计并创建平台身份迁移。
- 实现微信/抖音登录、会话签发、刷新、解绑和审计。
- 为平台登录补充限流、重复 code 防重放和错误码。
- 添加 OpenAPI 类型生成或共享 TypeScript 类型。
- 完成 API 单元测试和隔离数据库迁移测试。

### 阶段 B：共享客户端基础

- 初始化 Taro 应用和微信、抖音构建配置。
- 实现请求封装、Token 管理、错误处理、任务轮询和上传封装。
- 实现平台 adapter 和最小导航框架。
- 使用 mock 登录和 mock API 完成端到端客户端测试。

### 阶段 C：核心业务页面

按以下顺序实现，以便每一步都能独立验证：

1. 登录、首页、人物和章节。
2. 采访文字回答和普通录音上传。
3. 记忆、知识、时间线和冲突状态。
4. 剧本、分镜、视觉约束和版本状态。
5. 视频任务、播放、历史和失败重试。
6. 文件预览、上传恢复和离线页面恢复。

### 阶段 D：平台真机验证

- 先验证微信小程序完整核心流程。
- 再验证抖音小程序完整核心流程。
- 修复平台差异后再做并行回归。
- 取得平台审核需要的隐私、域名和类目材料。

### 阶段 E：发布

- 本地更新代码。
- 运行 API、Web 和小程序相关测试。
- 生成微信和抖音构建产物。
- 提交 GitHub。
- 服务器检查活动任务、数据库和环境备份，确认服务器 checkout 干净后拉取同一 commit。
- 只部署后端和 Web 必要变更；小程序构建产物分别提交平台审核。
- 生产迁移、健康检查和最小 Web 回归通过后，再提交小程序正式版本。
- 记录 commit、迁移版本、构建版本、审核版本和回滚信息。

## 7. 测试计划

### API 测试

- 微信登录成功、无效 code、过期 code、重复 code 和错误平台 code。
- 抖音登录同上。
- 同一平台身份重复绑定、跨平台身份绑定和解绑。
- 未登录、过期 Token、跨租户访问和权限拒绝。
- 迁移升级、空数据库启动和 `alembic check`。
- 登录限流、幂等和审计字段不泄露敏感信息。

### 小程序自动化测试

- 登录后首页加载。
- 人物和章节创建/编辑。
- 文字采访提交和任务状态更新。
- 普通录音上传、失败重试和任务恢复。
- 剧本分镜及视觉约束显示。
- 视频任务状态和播放地址处理。
- Token 过期后刷新。
- 网络断开、切后台、重新打开和重复点击。

### 真机验收

每个平台至少验证：

- 新用户登录和已有用户恢复登录。
- 一次完整文字采访流程。
- 一次普通录音上传流程。
- 一次章节剧本更新流程。
- 一次视频任务查看和成片播放。
- 低速网络、后台恢复、上传中断和失败重试。
- 隐私授权拒绝后的可用降级路径。

验收标准：核心流程不出现未捕获异常；所有失败均有可理解提示和重试入口；任务不会因为页面关闭而丢失；平台身份不会串租户；媒体地址不会暴露 OSS 密钥；小程序端显示的章节、剧本和任务状态与 Web 端一致。

## 8. 性能和单机约束

- 小程序端只做轻量请求和文件上传，不在客户端进行视频转码、AI 推理或大型文件拼接。
- 上传使用后端生成的受控上传流程，避免 API 容器长时间持有大文件。
- 任务状态采用退避轮询，页面不可见时降低频率，避免单台服务器被大量轮询占满。
- 首期目标是少量真实用户稳定使用，不把单台 4 核 8 GB 服务器当作高并发小程序平台。
- 发布前继续执行现有数据库备份、环境备份、容器健康检查和回滚保留流程。

## 9. 不纳入本期但需预留的能力

- 微信支付和抖音支付：保留统一订单、支付状态和回调抽象，等二维码收款需求准备好后单独实施。
- 实时语音：保留独立 voice adapter 和会话状态，不把实时语音逻辑混入普通采访页面。
- CDN：媒体 URL 和缓存策略保持可替换，当前继续使用 OSS 直读或受控代理。
- 多节点：任务租约、幂等键和数据库一致性继续保持，为以后增加节点保留基础。

## 11. 开始开发前的外部准备

用户需要提供或在本机配置：

- 微信小程序 AppID 和开发者权限。
- 抖音小程序 AppID 和开发者权限。
- 两个平台的服务器域名白名单配置权限。
- 微信和抖音隐私协议、用户协议及小程序名称/类目资料。
- 用于真机测试的微信账号和抖音账号。

AppSecret、平台私钥和生产环境变量通过服务器或本机安全配置注入，不通过聊天发送，也不写入 Git。

## 12. 完成定义

只有同时满足以下条件，才认为两个小程序首期完成：

1. 微信和抖音登录都能建立正确的用户/租户会话。
2. 两个平台都能完成文字采访、普通录音上传、章节更新、剧本查看和视频任务查看。
3. API、数据库迁移、共享客户端和平台 adapter 测试通过。
4. 两个平台至少各完成一轮真实设备回归。
5. 页面关闭、网络中断和 Token 过期不会造成任务丢失或跨租户数据泄露。
6. 生产部署遵循项目既定顺序，Git commit、服务器 checkout、运行镜像和迁移版本可核对。
7. 报告明确列出实时语音、支付、CDN、多节点和长期容量等未纳入项。
