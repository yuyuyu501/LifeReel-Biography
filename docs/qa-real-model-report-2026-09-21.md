## 主要发现

### R01：真实 LLM/视觉响应时间与固定 60 秒等待不匹配

`apps/api/src/lifereel_api/providers/openai_compatible.py:55` 的请求使用 `timeout=60`。隔离环境正常路径记录到 8 次约 60.44–61.70 秒的 ReadTimeout，覆盖记忆整理、采访评估、剧本、视觉分析、视频分镜；另外也有 5 次 17.63–57.19 秒的成功文字请求。此为本次样本结果，不可直接当作长期失败率。

分镜诊断仅在独立脚本中将一次请求的等待放宽为 180 秒，同一配置模型在 **108.55 秒**返回 HTTP 200 和合法两段分镜（1,932 输入 + 573 输出 token）。这证明至少部分任务在现有等待截止后仍可完成；不能证明所有超时都只需增加时间，也不能排除网关排队、负载或连接问题。

建议后续将不同任务的等待时间做成配置，配合后台任务状态/进度处理长请求，并保留“请求结果不确定时不盲目自动重发”的约束。此次未修改应用的超时设置，也未把诊断补入当作正式修复。

另一次剧本诊断等待 125.67 秒后未取得可解析 JSON。诊断包装器先解析响应再记录状态，导致 HTTP 状态未保存；无法确定是上游错误页还是其他响应格式问题，不能直接定性为模型返回非法业务 JSON。

### R02：音频专有名词需人工校对

输入为标准普通话合成声音，原文“浙江慈溪”“修船工”，输出“浙江慈禧”“修传功”。出生年份、搬家和蓝书包等主要内容保留，但事实型地名/职业错误会影响后续记忆。此样本尚不能评价真人麦克风、口音及噪声环境质量。

### R03：照片上色是推测，不能作为历史颜色还原

样本来自 [scikit-image 收录的 NASA astronaut 图像](https://raw.githubusercontent.com/scikit-image/scikit-image/v0.24.0/skimage/data/astronaut.png)，先转黑白再人工加三条划痕。恢复结果去除了明显划痕，脸部大体保持；上色却把已知橙色服装改成蓝色。徽章文字和纹理也并非逐像素保真。单张正脸样本不证明合照、严重损坏、低清或身份保持均通过。

对比图：[原图、损伤输入、黑白修复、上色结果](../tmp/qa-real-20260921/restoration-comparison.jpg)。

## 视频诊断经过及成片核验

由于真实采访/剧本未完成，在独立数据库准备了明确标记的**人工测试稿** `QA河边故乡（人工测试稿）`，16 秒、720p、16:9、原生音频，无人物肖像和参考声音：

> 清晨，河边的小村渐渐醒来，石桥下流过清亮的河水。远处青瓦屋顶映着阳光，风吹动岸边的树叶，记忆里的故乡总是这样安静。

正常分镜失败后，保存原始失败状态，再将 180 秒诊断得到的真实模型分镜写入这一隔离任务的恢复检查点。随后点击 Web“重新生成”，真实供应商完成两段及第二段尾帧续接，Worker 合成为最终视频。

- 文件：9,462,413 字节；H.264 1280×720；AAC 48 kHz 单声道；容器时长 16.213333 秒，视频流 16.137695 秒。
- FFmpeg 全片解码无错误；Web 实际播放到结束；原生菜单下载事件成功；刷新仍显示已完成；成片页检查未记录到前端 error 日志。
- 抽帧在 7.8/8.2 秒交界处保持桥梁、建筑、光线场景一致；仅作抽帧定性检查，未全面评价逐帧光流、音色衔接或镜头质量。
- 本地 Whisper 识别到完整主要旁白，含“清亮→清凉”“青瓦→清瓦”等同音差异。由于此项依赖 ASR，不能据此确定视频声音本身逐字有误或完全准确；真人听感仍可复核。
- 自动点击/键盘跳转没有得到可靠的位置变化，因此拖动/跳转未记为通过；不能仅凭本次自动化结果判定播放器缺陷。
