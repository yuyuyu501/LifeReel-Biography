# 个人微信收款码充值测试

## 使用范围

这是个人收款码的人工核实流程，不是微信支付商户 API。没有微信支付回调、自动查单、自动退款或自动到账。仅用于受控的小额测试，不作为公开运营的正式支付方案。

收款图使用本次提供的原始二维码，页面显示收款人 `yuyuyu（**翔）`。图片保存在被 Git 忽略的 `data/payments/`，不提交到仓库，也不将用户输入的单号视为可信到账凭证。

## 用户测试

1. 打开 <http://127.0.0.1:5173/wallet> 并登录。
2. 在线充值选择“其它金额”，输入 `0.01`，点击“确认支付”，在弹出的微信支付窗口中查看二维码。
3. 弹窗仅显示二维码和一句金额提示，不显示订单号、交易单号输入、提交或取消按钮。使用微信扫码并手动输入提示中的金额；建议用另一个付款微信账号测试。
4. 个人收款码不能自动返回支付结果。由收款方核实真实收款及付款人对应的家庭账户后，在服务器确认入账；付款人无需在网页填写交易单号。
5. 收款方按下一节核对真实到账并执行确认命令。当前订单每 3 秒查询状态，充值记录每 10 秒刷新。核实入账后自动刷新余额、关闭支付弹窗并显示成功提示；核实拒绝或接口异常会在弹窗内提示。网络错误不代表微信付款失败，请勿重复付款。
6. 没有付款时直接用右上角关闭按钮或 Esc 退出，余额及用户可见充值记录均不变化。已付款请勿重复付款。
7. 当前页面再次点击同金额的“确认支付”会复用待处理记录。充值列表只显示已核实入账的款项，不显示内部订单号、未付款、已取消或核实失败记录；数据库仍保留对账所需数据。

## 收款方核实命令

在仓库目录的终端执行，必须具有服务器访问权限。前端和 HTTP API 不提供入账审批权限；家人档案中的 owner 角色不等于平台财务管理员。

列出最近 50 条待处理记录（pending 或 submitted），包括内部订单号和家庭账户标识：

```powershell
docker compose exec api python -m lifereel_api.modules.billing.recharge_admin list
```

在**收款人的微信账单**查验实际到账，核对收款金额、交易单号、付款时间、付款人和家庭账户归属。页面不采集交易单号，因此当前仅适合受控测试，需要线下确认付款人与账户的对应关系，不能仅凭相同金额或相近时间猜测匹配。无法核实归属时不要入账。将以下占位符换成核实后的实际值（金额单位为分）：

```powershell
docker compose exec api python -m lifereel_api.modules.billing.recharge_admin confirm --order-id <订单UUID> --operator <操作人> --amount-cents 1 --wechat-transaction <真实微信交易单号> --received
```

`--received` 表示操作者已经查验真实到账。金额必须完全匹配订单；同一个真实交易单号全局只能用于一次充值；同一订单同一金额同一单号重复确认不重复入账。订单变更、钱包余额和流水在同一数据库事务内提交。

核实未通过：

```powershell
docker compose exec api python -m lifereel_api.modules.billing.recharge_admin reject --order-id <订单UUID> --operator <操作人> --reason "未找到对应收款，请联系收款方核对"
```

拒绝操作**不会退款**。实际已经付款但信息不匹配时，先人工核对，不应直接拒绝并忽略款项。核实终态不支持用户自行重新提交。

## 配置与保护

- `.env`：`MANUAL_WECHAT_ENABLED=true`；本机 API 的 `MANUAL_WECHAT_QR_PATH=data/payments/wechat-qr.png`。
- Compose 只读挂载 `./data/payments:/data/payments:ro`，容器固定读取 `/data/payments/wechat-qr.png`。异机部署须另外安全复制图片。
- `.env.example` 默认关闭；缺少二维码文件时也不允许新建充值或展示二维码。
- 暂停新付款后，已有订单仍可提交付款信息与核实。
- 单笔范围 ¥0.01–¥200，每个家庭钱包每小时最多新建 10 条付款意向；已取消、未付款记录不会永久占用名额。这只是基础限制，不替代正式上线防刷。
- 金额按整数分计算；客户端不能指定入账状态或余额；创建请求支持幂等，重试复用请求标识。
- 列表、订单详情、提交及取消按当前家庭隔离；二维码接口使用现有登录鉴权，响应禁止缓存。
- API 错误返回错误码，前端转换为中文。
- 不改动原有赠送额度及生成收费标准，不展示模型用量。

## 退款与后续接入

目前**没有钱包退款流程**。在微信中退钱或转回付款人，不会自动扣减系统钱包余额；不要在系统已入账并可消费的情况下直接线下退款而不对账。正式上线前应补齐退款、账务冲正、支付投诉及商户身份合规流程。

正式自动到账应接微信支付商户 Native 支付，使用订单专属二维码、签名验签、回调和主动查单、金额与商户校验、幂等处理。不得用个人微信监听、用户截图识别或“我已付款”按钮来自动记账。

自动化检查不发起真实支付，也不调用付费 AI。确认入账只操作隔离测试数据库，浏览器成功与失败流程使用模拟订单，真实扫码支付与收款核实由你完成。
