## 一、会议目标与证据边界

目标：让用户能够放心讲述、及时纠错、持续补充，知道系统正在处理什么，最终获得有个人细节且画面丰富的作品。按产品、前端交互、后端数据、采访 AI、影像制作和验收六个视角讨论；这些是分析视角，不代表已经召开真人会议或运行多个独立评审 Agent。

材料是一份含十项反馈的截图。未提供反馈用户的会话 ID、原始输入、模型输出、视频样本或操作录像，因此不能认定每个现象都已现场复现，也不能估计所有用户的发生比例。下文分别标记实现已确认、原因假设和产品建议。单一反馈来源的普遍性信心低，但通过源码直接验证的实现事实可以明确陈述。

最初讨论没有调用付费模型或执行线上生成。随后用户批准按文档实施，并明确人物一致性是“同一人物在不同镜头里保持稳定形象”，不新增全片数字人口播模式。常规实现验证沿用隔离数据库和模拟服务。

## 三、关键技术与产品决定

### 1. 纠错应覆盖整条事实链

建议流程：选择旧回答→编辑或发起澄清→形成修订记录→新版本生效→更新记忆与相关剧本→从当前有效信息继续采访。

- 保留原始录音、转录文本、用户修订和修订时间；原始资料与当前生效事实分开。
- 编辑回答只能由 interview 服务受理；memory、script 等服务通过现有命令/事件边界处理自己的数据，避免前端直接改多张表。沿用单数据库 Schema 分类。
- 为回答/事实引入版本与替代关系，按具体事实撤销或替代；一条回答里其他正确内容继续有效。
- 防止旧后台任务覆盖新版本；更正完成前，读取上下文时必须优先考虑已确认的新输入，不能继续使用已失效事实。
- 现有直接 answer 接口能覆写答案，但不会自动形成完整的修订、撤回和重算闭环，不能直接用作新功能的全部实现。
- 历史成片保留，标记资料已有更新；是否重新生成视频由用户决定，并说明费用。重试依靠幂等键避免重复扣费，自动免除哪些重生成费用需要另定产品规则。
- 不把不确定的同音字、姓名或地名自动替换为模型猜测。

示例：用户输入“我在章平工作”，后说“刚才地名写错，是漳平”。系统应确认或接受明确更正，让后续问答和剧本使用漳平，同时保留修订来源。是否采用这个例子的自动确认行为，需要以具体上下文和实体歧义测试决定。

### 2. 初稿就绪与采访结束是两个判断

建议分别维护素材是否足以成稿、可继续深入的线索、用户是否愿意继续。写出初稿后仍可继续补充，不把已生成初稿当作用户已经讲完。结束、换章和暂停应有明确的用户控制。

对简短回答降低回答负担，不强制最低字数或固定轮数。示例：用户说“1992 年我去了广州一家服装厂”，下一问可以是“刚进厂时，您主要负责哪道工序？”用户回答“踩缝纫机”，再问“第一天上手时，哪一步最不容易？”这些是提问示例，不能把示例中的工作难度、住宿或经历写进事实库。

拒绝回答、记不清、疲惫、想跳过不等于资料错误。尊重明确暂停与拒绝；把缺口留作未提供，不持续逼问。

### 3. 采访规划保持轻量、有状态

沿用现有 Agent/Skill 和独立服务结构，新增或完善输入澄清、事实修订、追问规划、回答深度评估和问题去重能力。没有必要因这十条反馈立即再增加一批 Agent 或数据库。

每轮按“识别更正/继续/暂停/改稿意图→收集相关有效事实与新输入→找当前具体缺口→生成少量候选追问→去重与事实检查→呈现一个问题”执行。用结构化结果支持控制，不将长篇内部推理展示给用户。

先使用规则与结构化字段完成可确定的校验，需要模型判断的步骤尽量合并，避免每个步骤新增一次串行模型调用。

### 4. 等待时间与实际处理过程一致

现有链路中下一句采访回应在记忆与剧本工作之后生成，这能解释等待感的风险，但实际各阶段耗时须通过时间戳验证，不能仅凭源码给出秒数结论。

建议先展示真实阶段及已等待时长；有足够历史样本后，再分别给排队、模型处理、视频片段和合成耗时的区间估计，样本不足时明确暂无可靠估计。进度百分比只用于可以测量的步骤，不做一直停在 99% 的假进度。

后续可将可验证的新回答先保存，快速给出基于最新有效上下文的采访回应；记忆整理、剧本更新在后台跟进。该改造必须处理修订版本、并发回复顺序、失败重试和保存状态，不能仅将现有串行代码放到多个线程。只有实际成功后才能显示“剧本已更新”。

实时语音可复用同样的修订与后台更新能力，不把每句语音阻塞在完整剧本生成上；实时语音的端到端效果不在本轮证据范围内。

### 5. 人物一致与镜头丰富分别处理

当前代码已经保存 story_skeleton，视频规划在已有 shots 时直接按剧本分镜执行。因此，单纯再添加“分镜”字段不能解决画面单一。

建议先按样片定位问题层级：事实太少、剧本重复、镜头功能重复、素材引用不合适，还是模型没有执行分镜。逐层检查后再决定是否调整提示词、生成策略或供应商。

分镜应各有叙事作用，如交代环境、呈现动作、展示关键物件或老照片、表达转折、收束；按实际内容选择，不能要求所有章节机械地包含相同景别数量。人物和画风保持一致，景别、动作、构图和素材可以变化。

“统一虚拟人”已按用户澄清确定为同一人物在不同镜头的视觉身份稳定。实现固定人物参考、逐镜头约束和实际成片验收，不新增数字人口播制作模式。

对照片/音频分别说明事实、画面和人物参考用途。用户选择的固定人物照片优先进入参考包，各分镜使用一致的身份参考；官方尾帧仅作补充衔接。程序核验参考来源与媒体哈希，不宣称自动识别人脸或保证真实模型的形象、动作、声音必然一致。

## 四、建议实施顺序与验收

| 批次 | 范围 | 验收重点 |
|---|---|---|
| 第一批：基本控制与采访连续性 | 01/02 修订链；03 新消息与状态；04 章节导航；05/07 追问规划；06 阶段信息；10 轻量教学 | 改错后历史可追溯、有效记忆与剧本一致；旧任务不覆盖新版本；短回答可继续深入；拒绝会停止；浏览历史不强制滚动；换章不丢草稿或重复创建会话。 |
| 第二批：效率与作品质量 | 06 耗时采样及回应解耦；08 分镜/成片验收；09 素材引导 | 记录真实分阶段耗时；回应与保存状态准确；镜头有不同叙事作用；照片音频引用可见、可选择；局部重试不重复扣费。 |
| 明确边界：跨镜头人物一致性 | 固定人物参考、分镜约束、成片抽帧与局部重做 | 模拟测试核验同一参考确实逐镜头传递；真实模型的脸型、五官、年龄、服装、镜头衔接仍需单独样片验收。 |

回归分三层：

1. 单元与接口：修订版本、来源失效、事件幂等、权限和并发；使用隔离数据库与 mock。
2. Web 操作：更改已发消息、提交前重新录音、读历史时收到新消息、下一章/返回、刷新恢复、任务失败/超时与新手引导。
3. 体验质量：中文同音字、人名地名、年份更正、单词式短回答、相关年代地区信息、反复拒绝、已问问题换说法、长对话遗忘；影像需核对脚本、逐镜头提示与实际视频。真实模型和视频的验收是单独有预算的活动，不混入常规发布回归。

尚待补齐的证据：第 02/05/07 项各自的原始输入与错误回复；第 08 项视频、对应剧本和分镜；第 06 项服务分阶段耗时。01 的“重来”还需在实际回访中区分修改已发送文字、纠正转录与重新开始整章。本讨论稿已给出保守默认方案，不依赖先拿到这些材料才能做基础改进。
