## 2. 公网 HTTPS 与 CDN

- TLS 1.2/1.3 实际握手成功，TLS 1.0/1.1 被服务端拒绝。未关闭证书校验。

本次响应未见 HSTS；登录/私有 JSON 响应未显式返回 Cache-Control。当前未观察到缓存泄漏，这属于启用 CDN 前需确认的缓存策略，不应直接认定已发生泄漏。

## 3. 真实 OSS 边界、并发和浏览器直传

以下为真实阿里云 OSS；后端保存完成时从云端逐块读取完整内容，服务器算出的 SHA-256 与本地一致。除浏览器注明项目外，协议边界用 HTTP 客户端驱动同一上传许可和确认接口。

| 文件 | 大小 | 原生 POST 上传 | 后端完整校验/保存 | 结果 |
|---|---:|---:|---:|---|
| JPEG | 20 MiB | 3.73 秒 | 0.77 秒 | 成功，SHA、末尾 Range、重复确认通过 |
| 文档 | 50 MiB | 浏览器实际上传 | 已保存 | 有效纯文本 SHA 一致，尾部 1024 字节 Range 206，刷新后素材仍在 |
| WAV | 500 MiB | 93.58 秒 | 5.11 秒 | 成功，SHA、末尾 Range、重复确认通过 |
| MP4 | 2 GiB | 350.11 秒 | 19.11 秒 | 成功，SHA、末尾 Range、重复确认通过；另一次浏览器实际上传同等大小视频也通过 SHA 与 Range 校验 |

文件用于传输边界：JPEG 添加尾部填充、MP4 添加合法 `free` atom，WAV 为合成静音；不是长达 2 GiB 的真实拍摄内容质量验收。最初文档 fixture 以 NUL 填充，被正确拒绝为 415；已换为有效 UTF-8 文档，通过浏览器重测。不得把该 fixture 错误计成应用上传缺陷。

追加检查均通过：

- 四种类型“上限 + 1 字节”在申请许可时返回 413；OSS 原生精确大小 Policy 拒绝实际超额内容（400 / EntityTooLarge）。
- 匿名对象读取 403；同一临时对象重复上传 409 / FileAlreadyExists；正确签名但过期的 Policy 返回 403 / AccessDenied。
- 实际 CORS OPTIONS 与上传通过；现有规则返回 `Access-Control-Allow-Origin: *`，本轮没有修改共享 Bucket 规则，私有对象仍需鉴权。通过不等于已收紧生产来源列表。
- 十个 4 MiB 文件同时向真实 OSS POST，10/10 成功（总体 3.09 秒）；十路并发确认的完整 SHA 均正确。
- 十个未完成许可允许签发，第十一个返回 429。
- 在已发送部分请求体后主动中断连接：后端拒绝确认缺失对象；用同一许可重新完整上传后成功。此为重新上传，不是断点续传。
- 本轮记录的云端对象已按精确键删除。浏览器对象额外通过 HEAD 确认 404；没有清空 Bucket 或删除原有业务对象。

浏览器“发送并更新剧本”还会触发后续内容处理。首次文档提交被尚存的本地存储 Worker 误领取，随后整理因测试存储模式不一致失败；停止该 Worker 后，视频的后续处理通过正确 OSS API 的 Mock 工作流执行。大文档的 Mock 剧本随后触发 2000 字符输出限制，详见问题 D03。**上传传输通过不等于大文档真实模型整理通过。**

证据：`oss-large-results.json`、`oss-extra-results.json`、`web-oss-results.json`、`web-oss-cleanup.json`。

## 5. 持续负载和压力

持续测试目标为 3600 秒：10 个有 1 秒思考间隔的客户端，经 Nginx 访问实际认证、数据库和两 API；业务混合包含八类列表读取、人物更新、1 MiB 文件上传、采访任务。中途加入已记录的故障窗口，并额外叠加 50 并发、零思考时间的 10 分钟读取压力。

50 并发读取已执行 603.78 秒，共 65,093 次业务请求，全部 200；107.81 请求/秒、P50 31 ms、P95 3171 ms、P99 4641 ms、最慢约 7968 ms。前约两分钟仍受 D02 单上游回退影响，08:35:39 UTC reload 后恢复两 API 分流。因此这组数值是实际混合运行过程的观测，不是纯双实例性能基准。

持续阶段已完成，含最终采样共 3616.39 秒：32,676 次请求（30,650 次读取、327 次上传、1634 次人物更新、65 次采访任务提交）。状态为 32,230×200、326×201、65×202、55×500；55 次 500 全部集中在主动停止数据库的故障窗口。整体 P50 16 ms、P95 187 ms、P99 2937 ms，包含故障和叠加压力期间，不能将其解释为无故障延迟。

撤去额外压力后，完整恢复采样覆盖 1171.70 秒、11,283 次请求，全部 2xx；各窗口 P95 在 47–203 ms。两 API 恢复期间内存分别从 139.3→139.8 MiB、162.3→162.2 MiB；两 Worker 结束约 35 MiB，容器最终检查未见 OOM。数据库内存从恢复期 150.1 MiB 至 163.5 MiB，结束有 40 个 idle 连接和 1 个检查连接；一小时观测不能证明不存在长期泄漏。

65 个持续阶段任务全部完成，均 attempt_count=1；加上故障演练后隔离库总计 71 个任务全部 completed，无 queued/running/failed。20 个测试采访 workspace 读取均 200；重复 charge 业务键组为 0，冻结余额为 0，最终健康检查通过，迁移版本 `20260921_0031`。数据库约 11.29 MiB；重复上传命中去重，最终只有 6 个素材，因此这不是不断增加海量历史数据的容量试验。

客户端、隔离服务及原有本机服务位于同一主机；照片与 OSS 测试部分重叠，50 MiB Mock 处理/日志也产生了额外资源干扰。不是独占负载机测试，不能外推为线上容量、真实 AI 并发或在线用户数。证据：`soak-results.json`、`peak-results.json`、`load-summary.json`、`final-checks.json`。

## 7. 新发现及后续范围

### D01 · P2：并发中转上传会返回 500

`apps/api/src/lifereel_api/modules/evidence/service.py` 的 `create_asset` 先查重，再写对象与提交资产。跨 API 竞争时两个请求均可能先查不到记录，后者提交触发 `uq_source_assets_storage_key`，未捕获后转为 500。

首次 20 次同素材上传出现 1 次 500；独立复现三组各 20 次，结果为 19/20、20/20、19/20 成功，失败均为 INTERNAL_SERVER_ERROR。数据库最终只有一个对应资产，下载 SHA 正确。影响是误报上传失败和额外重试，不是本次已观察到数据丢失。真实 OSS 原生直传并发确认的测试通过，不能将此中转端点问题笼统归为所有 OSS 上传失败。

建议参照直传确认的并发处理：在事务中捕获唯一约束竞争，回读同一租户/人物/哈希资产，保持返回幂等。证据：`fault-results.json`、`upload-race-results.json`、API 日志；本轮未修改源码修复此项。

### D02：测试负载均衡拓扑没有自动刷新上游地址

隔离 API1 容器由旧 IP 换成新 IP 后，虽然两个 API 都健康，Nginx 仍向旧地址尝试并回退到 API2。重载前 20 次读取均落在 API2；仅重载隔离 Nginx 后 40 次分布为 22/18。测试自建 upstream 与项目现有静态 `proxy_pass` 都没有在这次实验中展示动态重解析能力，但未对线上重建容器复现，因此不将其描述成已发生的线上宕机。

部署/扩缩容应保证网关刷新上游，或配置并验证动态服务发现；当前故障恢复结论包含这一人工 reload 步骤。证据：`routing-recovery.json`。
