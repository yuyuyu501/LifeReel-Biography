# 独立服务拆分执行与验收

本次目标是实际运行边界拆分，不能用新增目录、服务清单或两个队列消费者代替完成。既有提交 413131b 只作为起点。

## 执行顺序

1. 将账号、采访、记忆、剧本、媒体、计费、模型网关以及任务调度代码归入独立服务目录，建立各自的 Dockerfile、应用入口和配置；保留 Web 与小程序的外部 API 契约。
2. 落实内部认证、服务间调用、耗时任务独立执行和事务事件投递。接口必须保留租户范围、幂等、超时与失败恢复，不允许失败后偷偷回到单体执行。
3. 使用隔离 PostgreSQL、Redis、合成数据和 Mock 模型进行 Docker 联调、故障和重复投递回归。检查内存预算、迁移一致性与已有功能。
4. 全部通过后在当前分支提交并推送，服务器检查干净工作区和活动任务、备份数据库与环境、保留旧镜像，再拉取同一提交部署并核验运行代码。

## 必须提供的完成证据

- 每个服务有明确业务所有者、独立入口和可运行镜像，网关不执行领域业务。
- 采访与媒体任务在不同执行进程中运行，不回调旧 API 进程执行全部业务。
- 记忆、剧本、计费和模型调用经过显式内部接口，拒绝未授权与跨租户调用。
- 事件可实际投递、失败后恢复，重复事件不重复执行或扣款。
- 服务停机与恢复能够被健康检查和端到端测试观察到。
- 数据库暂保留现有 PostgreSQL 实例及关系数据；逐项记录共享读取及事务兼容边界，不把共享数据库报告为独立数据库。
- 既有功能回归、Docker 业务链路、数据库迁移及模型一致性检查通过。实时语音仅做协议与模拟回归，真实通话仍由用户手动验收。
- 发布报告同时包含提交 SHA、运行镜像、迁移版本、备份路径及未覆盖项。
