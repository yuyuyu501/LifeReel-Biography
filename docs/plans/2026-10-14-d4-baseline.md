# D4 记录组件基线决定

日期：2026-10-14。根据用户“先选用D4，固定前面可用部分，剩余问题后续考虑”的决定，
选定D4作为应用记录组件基线。随后用户明确要求完成应用接入、本地测试、GitHub同步及服务器发布。
应用实现版本为`d4-profile-20261014-v1`；发布以本地验证通过的提交为准。

## 固定的范围

基线名称：`D4 / entity-protocol-20261014-v2`。

| 环节     | 固定选择                                                                          |
| -------- | --------------------------------------------------------------------------------- |
| 候选提取 | `doubao-seed-2-1-lite-260915`直接读用户原话，输出人物与原子事实候选               |
| 事实核验 | `gpt-6.1-sol`读取原话和候选，允许纠正人物、对象、年份、状态、补漏与移除无依据内容 |
| 核验频率 | 每个提取回合都进行Sol核验；按需触发尚未验证，后续另作优化                         |
| 中间协议 | 固定人物ID、谓词、状态、`evidence`及`binding_evidence`；严格本地结构校验          |
| 输出格式 | 沿用本轮两渠道探测通过的`json_schema`请求方式，仍检查实际返回结构                 |
| 程序约束 | 人物、对象、出处、当前消息来源、单位与个人事件区分及待澄清处理                    |
| 出处保存 | 合并事实及人物绑定引文，保存消息ID、原话与字符位置                                |
| 字段映射 | 保留本轮程序映射作为实验基线；应用67字段需要单独适配                              |
| 生成设置 | 温度0、最大4096输出tokens；Lite关闭thinking                                       |
| 故障处理 | 保留错误与回执；传输故障不自动重试，不把失败当成空事实成功                        |

这个决定固定的是记录方案。Lite主聊及现有历史检索的产品方向继续保留，但本轮没有
对主聊引导效果重新验收。D4的组件成绩不能代替访谈界面、数据库或完整人物流程成绩。

应用新增独立`d4.py`：Lite直接提取人物与事实、Sol从原话重建完整候选，程序校验后适配为
资料表`changes`。它继续使用现有人物、账户、资料版本、手工确认、更正、使用范围及工作流
幂等机制。旧流程保留；`INTERVIEW_RECORDING_METHOD=legacy`可切回，`d4`启用新记录模块。

应用协议保留实验的主体、对象、原子谓词及双重引文，新增事件分组、同字段旧记录定位、
作品使用范围、化名和访谈策略。其余资料字段增加固定语义谓词及程序映射，上传素材仍由
真实上传模块建立；口述照片只能记录待提供状态。家人事实按人物合并，工作经历按事件合并。
素材范围补丁用于唯一`self`的素材状态与待续话题，身份和个人经历仍有原来的证据要求。

这是D4方法的产品适配版本，不能直接继承冻结实验分数作为产品分数。新协议、67字段、
会话策略及持久化须以应用测试另行判断。每轮全量Sol核验，旧Lite质量流程不再否决Sol候选。
严格结构请求通过现有模型网关，保留用量记录、不确定消费处理及远程RPC；温度0，最多4096
输出tokens。失败不自动重发、不保存未经核验的候选，工作流保留失败状态。

接受较长等待后，发布配置为Lite读取90秒、Sol读取240秒、回合预算300秒。
本地第一次三轮真实小样本第三轮曾在Sol读取120秒时超时，没有应用该轮更正；
失败记录保留在忽略的`tmp/d4-baseline-20261014/real-smoke.json`。复验使用新人物，
另存`real-smoke-v2.json`，不覆盖第一轮结果，也不改写原冻结实验的回执。

## 接受的现状

本批D4的84个案例轮次均完成。事实召回216/222=97.30%，事实准确率227/227=100%，
规定字段召回214/222=96.40%，出处完整221/227=97.36%，歧义安全保留10/10。
这些成绩由同一助手逐条审核，材料已用于调优，属于组件回归证据。

选定基线不等于达到整体验收门槛。先固定已有改善，后续修复在新的版本中进行，
保留当前成绩和原始输出，不为宣称通过而降低原门槛。

| 后续项目       | 当前缺口                                         | 当前处理                                 |
| -------------- | ------------------------------------------------ | ---------------------------------------- |
| 事件结构       | C08两轮保存转岗叙述，但未拆出入职年份            | 保留原话及叙述；后续修结构提取           |
| 字段路由       | C22两轮迁居事实正确，表格栏目与预定目标不同      | 接入67字段时明确映射契约                 |
| 必要出处       | 六条正确事实缺少话题、行动者或单位依据           | 保留原消息；后续补齐关联证据             |
| 素材与待续范围 | 冻结规则误拦C16四个目标                          | 将已完成的离线修复作为候选补丁，单列成绩 |
| 待澄清去重     | 部分相同事件仍有重复澄清条目                     | 后续按事件与人物集合核对合并             |
| 按需Sol        | 本轮仅验证全量核验                               | 当前保持全量核验作为基线                 |
| 完整流程       | 新人物、67字段、持久化、更正撤回和访谈引导未验收 | 应用接入后独立验证                       |

保留原消息只提高可追溯性，不自动补足已生成事实的出处，也不将待核对内容变成确定
记录。真实歧义继续澄清，用户拒答与使用限制继续遵守。

## 素材修复的版本边界

`entity-v2-metadata-scope-replay-v1`仅放宽唯一`self`的素材状态及明确待续话题。
它复用了同一批模型输出，恢复D4六条有依据内容，其中四条是目标事实。回放成绩为
召回220/222=99.10%、准确率233/233=100%、字段218/222=98.20%、出处227/233=97.42%。

该补丁已完成离线复核，尚未进行新版本真实复测。采用时须标注为“D4加素材范围补丁”，
不能用99.10%替换冻结D4真实测试的97.30%，也不放宽身份或个人经历的证据要求。

## 发布与回退

本次发布目标是固定可运行的D4阶段版本，不宣称整体访谈验收通过。先完成本地验证，
再提交、推送现有`main`，为同一提交建立`d4-baseline-20261014`标签。后续修改应另建提交，
保留该标签；需要退回本阶段时可按该标签的精确提交重新构建部署，不覆盖数据库新增资料。

服务器操作使用`deploy/d4_baseline_release.py`的prepare/build/deploy/verify阶段。
源码必须是已推送的精确提交；发布前检查任务、数据库和环境备份、保留旧镜像；
迁移维持`20261012_0045`，本次没有新增数据库迁移。

发布记录位于`/opt/lifereel-deploy/d4-baseline-20261014`，备份及旧镜像清单位于
`/opt/lifereel-backups/d4-baseline-20261014`，均限管理员读取。
`verification.json`记录实际发布SHA、镜像、迁移和运行源码摘要，不能只凭Git一致判断发布完成。
已有新数据时不直接恢复旧数据库；紧急应用回退优先复用保留的镜像和配置，保留当前数据库。
