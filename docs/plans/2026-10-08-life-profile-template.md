# 人生资料表详细模板

日期：2026-10-08。状态：用户已批准；12 类、67 字段的版本化模板、表单与 XLSX/Markdown 导出已实施，整合验收已通过；真实语音及真机另行验收。

配套文件：[人生资料表、写书与影像流程改造计划](2026-10-08-life-interview-book-video.md)。下面定义用户看到的资料内容、AI 该补问什么，以及数据如何保留来源。资料类别用于整理，不是必须依次完成的采访章节。

## 1. 填写原则和展示方式

每个人物一份资料表，页面按类别显示“项目、当前内容、处理状态、来源、编辑”。时间、人物等经历明细在展开记录后编辑，不把所有元数据铺成几十列。AI 可以从一段回答填写多个项目；用户直接改表也会成为当前有效资料。

“基础”仅指开始整理需要的信息；大多可以从现有人物档案带入。“建议”指适用时优先补充，不是拒绝继续操作的硬门槛。“可选”和“条件”均可跳过。默认采访范围为截至目前的人生，用户可随时缩小到某段经历；准备状态必须随范围变化重新判断。

每次优先问一个主要问题，可附一个简短追问。先接住用户正在讲的内容，再补相关空缺；不按下表逐格机械提问。用户要求先聊工作时，不能因童年未填写而拦住。

基础事实优先来自用户明确表达或已有有效档案，不从姓名、照片、婚育、职业推断性别，不从照片估计年龄。未讲过的细节保持为空或未知；不为写作效果补造对白、情绪和经历。

## 2. 主表字段：A–D

方括号 `[]` 表示可重复记录，不表示要求用户填写代码。下面的字段键用于稳定映射，中文名称用于界面。

### A. 基本信息与讲述范围

| 字段键 | 用户看到的项目 | 类型 | 优先级/条件 | AI 补问示例 |
| --- | --- | --- | --- | --- |
| `identity.preferred_name` | 书中称呼 | 短文本 | 基础，优先复用人物称呼 | 书里希望怎么称呼这位人物？可以用化名。 |
| `contributors.records[]` | 讲述者及与人物的关系 | 角色与关系列表 | 基础，可自动带入；代述时澄清 | 这些是您的亲身经历，还是您替家人讲述？ |
| `scope.coverage` | 想记录的人生范围 | 全人生/时期/主题 | 基础，默认全人生；写书前确认 | 您想先记录整个经历，还是从一段最想讲的故事开始？ |
| `identity.birth_time` | 出生时间 | 时间原话与精度 | 可选 | 出生年代大概是什么时候？不清楚可以留空。 |
| `identity.birth_place` | 出生地与成长地 | 地点列表 | 建议，可只到城市/乡村 | 最早住在哪里？后来有搬过家吗？ |
| `identity.gender` | 自述性别 | 可空短文本 | 可选，不默认追问 | 仅在用户主动提供或明确要求写入时记录。 |
| `identity.aliases` | 曾用名、亲友称呼 | 文本列表 | 可选 | 家里人有没有一个经常叫您的称呼？ |

## 5. 可重复记录结构

### 5.1 通用经历记录

| 项目 | 数据含义 | 填写规则 |
| --- | --- | --- |
| 记录 ID | 稳定的 `record_id` | 系统分配，修改时间或标题不能换成新经历 |
| 事件名称 | 简短标题 | 可从原话概括，不增加未提供的事实 |
| 所属类别 | 一个或多个类别引用 | 同一事件可同时属于工作与转折，用同一个 ID，避免重复计数 |
| 时间原话 | 如“差不多八十年代末” | 保留原意，不强迫精确年份 |
| 时间结构 | 可空起止时间、精度或相对顺序 | 有依据才填写；不自行把“约”换成精确日期 |
| 地点 | 原称呼及可确认的地点 | 不索取精确住址；不确定的地名可保留原话 |
| 相关人物 | 稳定人物引用、关系与称呼 | 可使用“母亲”“同事”等，无需真实全名 |
| 发生了什么 | 事件经过 | 优先补充具体过程；没有资料则留空 |
| 本人做了什么 | 当时的行动或决定 | 不将外人的行为误写成主角的行为 |
| 当时与现在的感受 | 用户明确说出的感受 | 分开记录，不由模型代为推断 |
| 结果与影响 | 当时结果、后续变化 | 有依据才填，不强求“成功”结局 |
| 值得保留的原话 | 引语、口头表达 | 标明说话者与来源，模型润色不得冒充真实引语 |
| 证据与修改历史 | 回答/转写/手填/资产/版本 | 见第 6 节；正文素材与审计历史分开 |
| 处理与使用状态 | 空缺、确定性、冲突、是否可进入作品 | 分别存储，不能以一个“已完成”代表所有状态 |

不是每条经历都要填齐以上细节，写作准备评估判断哪些缺项影响当前主题。AI 对同一经历继续补问时补充原记录；两件不同事件即使发生在同一年，也应保留独立 ID。

### 5.2 人物、学习、工作与照顾记录

| 记录类型 | 专用字段 | 共享信息 |
| --- | --- | --- |
| 人物与关系 | 称呼、与主角的关系、关系时期、相关经历 ID | 来源、使用范围、时间精度；同一人物跨类别复用引用 |
| 学习经历 | 学校/师傅/自学方式、学习内容、起止时期、变化或收获、相关事件 | 不默认有学历或证书，不精确推算入学年份 |
| 工作经历 | 单位/地点、角色、劳动内容、起止时期、转变原因、相关事件 | 允许务农、家务、经营、临时劳动，避免假设标准职业路径 |
| 照顾经历 | 照顾者、被照顾者、双方关系、时期、具体事件 | 不因照顾孩子而推断是父亲/母亲或推断性别 |
| 媒体关联 | 现有资产 ID、文件类型、说明、相关人物/经历、允许用途 | 不在资料表中保存文件内容或临时访问凭据 |

人物称呼引用只用于叙事与事实关联，不把每位提到的亲友自动建立为可登录账号或新的采访对象。书中称呼可以采用化名，不能因此自动改账号资料。多位家人代述时保留各自的讲述者引用，并将每份证据关联到实际讲述者，不能把后来的代述人覆盖成所有历史内容的来源。

## 6. 状态、确定性和来源

### 6.1 处理状态

| 状态 | 页面文案 | 补问与写作用法 |
| --- | --- | --- |
| `empty` | 待补充 | 当前没有内容，适用且与话题有关时才补问 |
| `filled` | 已有资料 | 有实际内容，还需检查来源、冲突和使用范围 |
| `unknown` | 暂不清楚 | 不编答案，可在用户后来想起时补充 |
| `deferred` | 暂时跳过 | 允许用户稍后继续，不在接下来几轮反复追问 |
| `declined` | 不愿回答 | 不主动重复追问，用户主动重开话题时才更新 |
| `not_applicable` | 不适用 | 不继续追问该分支，不计作故事素材 |

确定性与冲突另存：用户明确陈述、用户明确确认、用户自己不确定、待澄清冲突、待整理历史素材。明确陈述可直接整理入表，无需每一项弹窗确认；有争议或指代不明时再问。模型提取置信度不能冒充用户确认。

每项单独记录是否允许进入书稿/影像、是否只用于内部资料、是否需要化名。可见范围沿用现有租户/人物授权，不因为“能编辑”就默认可对外分享；“不确定”和“私密”是不同属性。撤回使用权后同步收紧下游生成与导出规则。

### 6.2 来源与版本元数据

每次保存关联以下信息：资料版本、条目和记录 ID、来源类型、来源对象与版本、必要的原话片段、讲述者、变更者、保存时间、被更正条目以及变更原因。

来源类型至少区分文字回答、录音转写、实时语音证据、手动编辑、已有资产和历史迁入。当前资料展示最近有效来源，可展开历史。普通导出带来源摘要，历史审计不默认全部导出。

同一来源的重试按来源 ID 和版本去重。更正使旧值退出当前素材，但旧值及证据保留；旧记忆回放不能重新生效。手改保留操作者与版本，模型不能把手改内容伪标成录音原话。

## 7. 填写和纠错示例

以下均为虚构测试内容。

用户第一次说：“1988 年，我去泉州的工厂做工。”资料表建立一个工作记录和对应经历 ID，时间为 1988 年、地点为泉州、行动为去工厂做工。性别、准确年龄、岗位和感受仍为空；这一个短句不够支撑一章 1000 字。

第二次用户说：“前面记错了，是 1989 年去漳州，不是 1988 年去泉州。请改过来。”系统修改同一经历的当前时间与地点，保留旧来源，更新相关时间线并关闭明确更正导致的旧冲突。原经历仍只有一条；不要求用户返回第一次回答进行编辑。

若随后讲明找工作的原因、到厂后的具体劳动、一次困难、自己的应对以及后来的影响，这个主题可以进入局部写作评估。童年空白不阻止写这段工作，但页面仍不能显示“整个人生资料已齐全”。

用户说：“没结婚，这部分不适用。”关系分支标记不适用，不继续问伴侣与婚礼；照顾经历仍可独立适用。用户说：“年份记不清，大概是后来搬家前。”保留原话和相对顺序，不硬写某年。用户说：“这件事我愿意记着，但不要写进书。”记录内部可见与作品禁用，不能算作可用写作素材。

手动编辑时，页面显示“保存”和成功版本。若编辑期间 AI 已更新同一字段，提示最新值并保留用户草稿，不直接覆盖。删除某条当前记录也保留可追溯的版本，相关书章标记来源变化。

## 8. 导出给用户自行写书

首版在线编辑资料，下载 XLSX 或 Markdown。导出标题包含人物称呼、资料版本与导出日期。两种格式来自同一冻结快照，下载过程中发生编辑也不混入另一版本。默认不含内部私密内容；有权限的用户可显式选择包含它们，并在文件中保留使用限制。

| XLSX 工作表 | 内容 |
| --- | --- |
| 说明与概况 | 人物称呼、资料/模板版本、选材范围、可写主题、仍缺内容、导出范围说明 |
| 资料总表 | A–L 各项的中文名称、字段键、记录 ID、当前值、处理状态、确定性、使用范围及来源摘要 |
| 经历明细 | 稳定经历 ID、类别、时间原话/精度、地点、人物、经过、行动、用户自述感受、结果/影响与来源 |
| 人物与关联 | 称呼/化名、关系、学习/工作/照顾记录，以及关联经历 ID；不推断人物身份 |
| 来源与素材 | 当前使用的证据摘要、版本、资产 ID、文件显示名、素材说明与用途限制 |

时间模糊时按文本保留，不能被表格转换为精确日期。自由文本作为文本单元格写入，不作为公式执行。没有填写的字段明确标注状态，不填“无”冒充用户回答。重复引用同一经历使用同一 ID，不复制成多件事。

媒体仍存 OSS，表格导出不打包照片、录音或视频，不输出访问密钥或临时签名链接。来源原话摘要遵循条目使用限制，不能借来源栏泄露被排除的内容。

Markdown 采用 A–L 分类、经历小标题和必要来源标记，适合直接查看或作为写作素材。支持导出局部范围；不输出被更正的旧值作为现行事实。文件仅是导出快照，用户在 Excel 改动后不会自动回写网站；离线回导留到后续版本。

## 9. 模板对应的准备评估

不设置“12 类必须全部答完”。采访处理情况按适用项展示具体数量和状态；可写判断只看当前有效、来源可核验、允许用于作品的素材，按人物和用户选定范围生成结论。

| 样本 | 应有判断 |
| --- | --- |
| 各类都只有一个词，或全部勾了跳过 | 没有可写内容；已处理数量不等于素材充足 |
| 一个丰富事件，有来龙去脉、本人行动及影响 | 该主题可进入写作；其他人生阶段仍缺资料 |
| 多个主题足够组成已确认的小书目录 | 当前范围可写；提示前往写书或继续补充 |
| 有较多文字，但都是 AI 推测或被撤回使用的内容 | 不能作为可写素材，指出来源或使用范围问题 |
| 时间不精确，但事件经过可信且不矛盾 | 可以使用模糊时间写作，不强制追问具体年份 |
| 某个书章依赖尚未澄清的关键矛盾 | 该主题待澄清；其他无关主题仍可写 |

每个建议书章列出支撑条目、资料版本和仍缺的具体细节。初版规则需用固定样本验证短答不能误过、丰富局部故事能通过、更正后结论刷新。书稿阶段再验证实际 900–1100 有效字符及事实边界，不能将准备评估当作生成质量保证。

## 10. 首版交付边界

实施时需交付版本化模板、可操作的 Web 表格、AI 结构化更新、人工编辑、缺项与可写提示、审计来源、XLSX/Markdown 导出，以及写书/影像的新来源契约。小程序复用字段与状态，在现有页面内适配展示和编辑。

无需新增身份证等身份采集、上传真实人脸的强制步骤、逐格确认弹窗或固定顺序答题。暂不做离线表格导入、表格自定义字段编辑器和多人实时协同光标；跨设备修改仍通过版本冲突保护。

本文件定义已批准的模板及验收规则，不能为迎合当前实现而降低要求。详细实施顺序、迁移、测试与发布条件以[主计划](2026-10-08-life-interview-book-video.md)为准。
