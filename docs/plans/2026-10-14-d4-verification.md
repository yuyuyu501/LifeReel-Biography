# D4 核查与写入修复对照

本轮在首次真实调用前冻结。生产仍使用 `2b0a5ed` / `d4-baseline-20261014`。
本轮仅本地修改与验证，不提前提交、推送或部署实验链路。

## 假设与实现

旧实验不能证明核查语义准确率低：成功保存的样本事实都有支持，但存在漏记、
字段路由、错误冲突、重复、引文不足及通道失败。分别处理，不把所有失败归因于模型。

共同修复：取消 event_action 的默认工作/家人路由，要求具体语义谓词；
跨字段工作经历 ID 不得写入职责字段，可靠的单值字段可解除错误关联；
仅泛称单位加有原话支持的名称补全允许细化，两个具名单位仍冲突；
同事件欠债原因的拒答统一为未披露，原始表达保留出处。

增强核查（reasoning/combined）：Sol 只接收 Lite 拟回复，不接收 Lite 事实候选，
从原话独立重建；逐句 coverage 标明事实候选、歧义、控制或无事实；
actor/action、必要时间、对象、拒答/未知话题和极性均须提供逐字出处；
关联旧事实时明确 new/reaffirm/refine/correct/conflict 和原子事实下标。
程序校验记录、主体、谓词、事件、旧出处、状态及年份/否定变化，禁止用细化或重申
掩盖互斥冲突。明确更正只替换相关原子事实。必要上下文附到持久化证据。

增强核查输出上限由 4096 提至 8192 tokens，Lite 和普通 D4 仍为 4096。
这是多项措施的组合比较，不能单独归因于独立重建或输出上限。它不请求隐藏思考过程，
也不证明程序能判断中文语义。coverage 的 no_fact 分类仍须人工复核。

## 冻结评测

五个新合成案例，每组十轮，两组共最多四十次请求，无自动重试。
`baseline` 为同一新版代码的普通 D4；`combined` 为独立核查加现有结构化历史检索。
两个渠道和温度保持一致。交替组顺序；每例用正常新增人物/访谈 API 创建空资料，
独立测试数据库，以实际原话记录及流程对象调用生产记录路径，并刷新核对保存结果。
只有创建人物必须的系统称呼作为种子，它不参加成绩；人物实际称呼由访谈披露。

材料及目标字段在 `deploy/tests/interview_verification_experiment.py` 的 CASES 固定。
V01–V04 共 30 个最终有效事实；V05 专测未解决冲突，不将两种年份当已确认事实评分。
每条最终事实、字段、出处、重复、隐私和纠正都人工核对，额外保存事实也逐条审核。
失败回合披露仍在召回分母；记录失败及未知消费，不用有问题的结果触发付费重试。
连续失败两次停止当前人物；不删除失败、不混算旧 v1/v2 成绩。

这是主动披露的记录轨，不根据它评分引导或联想收益，不宣称全67字段或整体访谈验收。
对照两组用同一套新材料，旧报告保持不变。输出目录保存冻结清单、源码归档、所有
请求/回执、每轮表格及核查日志。人工核对并非独立盲审，结论仅适用于这套小样本。
