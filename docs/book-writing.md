# 写书服务

## 使用流程

Web 左侧导航选择“写书”，在“人生书架”选择人物并创建或打开书籍。每位人物一本书，目录沿用采访章节；书名创建时可填写。

在目录选择章节，点击“生成本章”，或选择“生成全书待写章节”。整书生成跳过没有资料或已经同步的章节。任务在后台执行，离开或刷新页面不会丢失；完成后显示实际字数。默认目标为每章 1000 字，AI 成稿验收范围为 900–1100 个汉字、字母及数字，不计标点和空白。

生成使用当前记忆中的事实。已私密、争议、被替代、旧回答版本及未解决冲突相关的事实不作为来源；素材不足时要求继续采访。引用和字数校验不等于真实模型文学质量或语义事实准确率的保证，成稿仍需用户核对。

“编辑正文”保存新版本，“版本记录”查看旧稿。重新生成和人工编辑都保留历史版本；失败不覆盖已有稿件。采访资料补充或更正后，旧稿标出“资料已更新”，由用户主动生成新稿；不会自动扣费重写。

至少一章成稿后可导出整书 TXT 或 Markdown。导出包含目录，并标注未成稿及资料已更新的章节；需要登录和所属租户权限。当前不提供排版 PDF、印刷或电子书发行服务。

## 服务边界与运行

- API：`services/book/`，独立 Dockerfile；路由 `/v1/books`。
- 执行器：`workers/book/`，独立 Dockerfile；持久任务 `book.chapter.generate`，写书 lane 并发为 1。
- 数据：`book.books`、`book.book_chapters`、`book.book_revisions`；迁移 `20260930_0043`。
- 模型：沿用 `SCRIPT_LLM_MODEL`、流式选项及现有模型网关，无新密钥。先组织提纲再生成有来源引用的正文；结构、引用和字数失败最多再尝试一次。模型未配置时明确报错，不返回模拟书稿。
- 钱包：沿用现有文字计费规则；按量模式已发生的 AI 用量会计费，包括结果验证失败的调用。按成功章节模式只结算成功章节。重复提交的同一个请求不重复创建任务。
- 一致性：生成前后校验来源摘要和稿件版本，冲突不会覆盖新稿；任务、稿件发布和钱包 Outbox 同事务提交。

生产 Compose 为 book 和 worker-book 各设置 256 MB 上限。数据库仍为单库，新增服务不要求新数据库账号或 OSS Bucket。

## 测试与发布

单元/API 回归位于 `apps/api/tests/test_books.py`，PostgreSQL 升降级测试位于 `test_book_migration.py`，Web 回归位于 `apps/web/src/pages/BooksPage.test.tsx`。发布测试使用隔离数据库、合成资料和模拟供应商，不调用付费 AI、短信、支付或视频。真实文学质量须独立验收。
