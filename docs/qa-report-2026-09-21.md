## 发现的问题

### F01 · P2：迁移缺少三个模型声明的外键

在空 PostgreSQL 执行 `alembic upgrade head` 成功后，`alembic check` 报 `New upgrade operations detected`：

1. `evidence_uploads.chapter_id → chapters.id`。
2. `source_assets.chapter_id → chapters.id`。
3. `source_assets.derived_from_asset_id → source_assets.id`。

位置：`apps/api/alembic/versions/20260916_0027_chapter_asset_references.py:20`、`:33`、`:37`；该迁移只增加列，未创建模型要求的 `ON DELETE SET NULL` 外键。

影响：通过迁移创建的数据库缺少引用完整性和删除置空约束，与自动建表测试库结构不同；可能留下悬空引用。应新增修复迁移，并让 CI 执行模型一致性检查，而不只检查升级成功。

证据：`tmp/qa-20260921/migration-check.log`。

### F02 · P2：纯实时语音更新后剧本同步状态错误

复现：进入尚无文字回答的新章节，启动实时语音，等到“知识和剧本已更新”及新剧本出现，挂断，刷新页面。

实际：剧本已持久化，右侧仍显示“最新内容尚未同步”，中间显示“等待内容”。通话中也会同时出现“知识和剧本已更新”和未同步提示。

位置：`apps/web/src/pages/InterviewRoomPage.tsx:264`、`:535`。同步状态只读取 `latest_workflow`；实时语音更新链路不创建文字 turn 工作流。

影响：用户可能误判保存失败，重复生成并再次计费。应把语音更新后的剧本版本/更新时间纳入同步状态判断，并补充纯语音场景回归。

证据：`tmp/qa-20260921/voice-status-mismatch.png`、`voice-active.png`。后续普通录音提交生成了 turn 工作流，状态随之恢复“已同步”，进一步印证判断分支差异。

### F03 · P2：人物必填字段显式 null 导致服务器错误

对测试人物分别执行：

```http
PATCH /v1/persons/{id}
Content-Type: application/json

{"display_name": null}
```

`{"is_subject": null}`、`{"is_minor": null}` 同样复现。三者实际均返回 `500 / INTERNAL_SERVER_ERROR`，应在请求验证阶段拒绝并返回 422。失败事务已回滚，原记录仍可读取，API 随后正常。

位置：`apps/api/src/lifereel_api/modules/identity/schemas.py:22`、`:27`、`:29`；`apps/api/src/lifereel_api/modules/identity/service.py:37`。PATCH Schema 允许 null，而对应数据库列非空，更新服务直接写入 null。

影响：错误客户端输入被当作服务器故障，污染 5xx 指标；本机还观察到该异常后复用连接的一次重置。正常 UI 未触发，但公开 API 边界必须处理。应区分“字段未提供”和“显式 null”。

证据：`tmp/qa-20260921/boundary-results.json`、`boundary.log`、`api-final.log`。
