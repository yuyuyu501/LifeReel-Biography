# ADR 0005：记忆档案与采访入口统一

## 状态

已接受。

## 背景

原流程把“素材”和“记忆”拆成两个工作步骤，导致同一份采访文件既像待处理素材，又像人物记忆的一部分。实时采访已经能够在聊天中接收照片、文档、音频和视频，继续保留独立上传页会产生重复入口，并弱化文件与人物、章节和对话上下文之间的关系。

## 决策

上传入口只保留在采访聊天。底层 `Evidence` 服务、私有对象存储、类型限额、转写与分析能力继续保留，供采访工作流调用；用户侧不再暴露独立素材操作页。

`/memories` 改为按人物隔离的只读记忆档案，统一展示人物小传、关系图谱、事件时间线、冲突和采访中上传的文件。历史 `/evidence` 地址重定向到 `/memories`。

知识图谱由 Memory 服务从有效主张、实体和时间锚点派生。每个节点与边保留来源主张 ID；私密和存疑主张不进入图谱；未明确说明的关系不得由系统猜测。

## 结果

- 用户只在讲述发生的地方新增资料，工作流由六步收敛为五步。
- 既有文件和 API 不迁移、不丢失，仍按租户、人物和采访会话隔离。
- 记忆页成为浏览与理解人物的档案，而非第二个编辑工作台。
- 图谱提供可访问的关系索引和原话追溯，避免只依赖 SVG 图形表达。
