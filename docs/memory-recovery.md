# 采访记忆整理的校验与恢复

## 行为

记忆陈述、知识图谱、人物小传均以 JSON Schema 明确字段类型和枚举，响应经
Pydantic 校验。图谱来源必须来自本次输入，冲突须有至少两个不同来源。空值、
非法引用和超长小传不会被默默截断或伪造替代。

格式错误携带具体字段路径和校验类型，要求 AI 根据相同原始来源纠正一次。
连接失败或限流最多退避一秒重试一次；读取超时可能已产生费用，不盲目重新提交。
首次调用和纠错共用两次尝试上限。现有兼容客户端对于不支持 JSON 模式的 400
响应仍可退回普通模式；被拒请求和实际 token 回执继续按原计费机制处理。

后台日志记录工作流 ID、步骤、尝试次数、失败字段及错误类型，不输出原始私密
对话、模型回复或凭据。最终失败的诊断也保存在工作流 script_brief 中。

## 断点

采访工作流中，每条通过校验的记忆陈述独立提交；图谱及小传分别在成功后保存
检查点。检查点绑定来源内容、审核状态、模型及服务地址摘要。来源变化后会重新
整理；来源未变时跳过已完成步骤。信息缺口判断也保存结果，剧本失败时可复用。
普通独立的记忆 compile API 保留原事务行为。

采访执行使用跨事务的会话锁，重复队列消息不会再次调用 AI。聊天原文始终保留。
图谱成功而小传失败时，图谱可以是最新版本、小传是旧版本，工作流仍标为失败；
它们不再为追求原子更新而共同回滚。

## 限制与费用

新恢复策略每轮最多执行三次，失败后手动重试冷却 30 秒；前后端同时限制。
旧工作流的历史 attempt_count 保留，新策略单独计数，允许部署后修复历史错误。
新策略期间该工作流累计已结算 AI 费用达到 1.20 元后，停止后续记忆调用和重试。
这是停止阈值，并非退款或精确账单封顶：刚完成的调用可能让累计费用超过阈值，
未知用量仍由原钱包待结算机制阻止盲重试。已使用 token 依然按实际回执计费。

前端始终显示已保存的聊天与已有剧本。最新回答尚未更新剧本时，显示
“最新内容尚未同步”；若剧本已完成、仅追问失败，则保留真实的同步状态。
重试耗尽时按钮禁用并提示联系管理员，仍可查看历史内容。

## 验证

回归覆盖非法枚举、JSON/字段错误、未知图谱引用、隐私日志、网络重试上限、
不重试不确定的读取超时、已完成图谱/记忆断点保留，以及前端过期剧本和重试状态。
