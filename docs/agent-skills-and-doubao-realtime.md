# 对话 Agent、记忆 Skill 与剧本 Skill

## 官方协议核对（2026-09-22）

本项目当前使用豆包实时语音 3.0 / Seeduplex 全双工接口，而非历史文档中的二进制接口。

- [端到端实时语音—全双工版本](https://docs.volcengine.com/docs/DoubaoVoice/endtoend-realtime-voice-full-duplex-version?lang=zh)，页面更新日期 2026-09-11。
- [接入必读](https://docs.volcengine.com/docs/DoubaoVoice/access-mustread?lang=zh)，页面更新日期 2026-09-04。
- WebSocket：`wss://openspeech.bytedance.com/api/v3/duplex/realtime/dialogue`；`session.model = "1.2.6.1"`。
- 纯 JSON 文本帧；在 `session.create` / `session.update` 的 `session.tools` 中声明扁平结构的 `type=function`、`name`、`description`、`parameters`。动态更新 tools 是全量覆盖。
- 服务端发送 `response.function_call_arguments.done`，其 `items` 中包含 `call_id`、`name` 和 JSON 字符串 `arguments`。
- 客户端发送 `conversation.item.create`，其 `items` 使用原 `call_id`、`role=tool`、`content=[{"type":"input_text","text":"JSON字符串结果"}]`。
- 同一事件有多个调用时，在一次结果事件中合并各调用结果。不要混用其他厂商的 `function_call_output` 结构，也不自行增加未在该页确认的 `response.create` 事件。

接入必读中另有将结果放入 `output` 的概括描述；本实现遵循详细接口表和 Function calling 的完整示例，使用 `role=tool` 的 `content` 数组。

## 运行方式

`modules/orchestration/skills.py` 提供应用级可执行能力，不是给开发工具安装的个人 Skill，也不是单独启动的服务。文字和语音入口使用同一实现：

| Skill | 职责 | 使用模型 |
| --- | --- | --- |
| `MemorySkill` / `sync_memory` | 整理来源、知识图谱、时间线、更正与冲突 | `MEMORY_LLM_MODEL` |
| `ScriptSkill` / `update_script` | 评估资料充分性，按有效事实与创作要求更新剧本 | 评估使用 `INTERVIEW_LLM_MODEL`；生成使用 `SCRIPT_LLM_MODEL` |

对话继续由实时语音模型负责；文字采访使用 `INTERVIEW_LLM_MODEL`。这些角色可以使用同一模型，也可以分别配置，不强制增加模型数量。

实时语音的完整 ASR 发言进入有界内存队列，增量转写不会直接写入记忆。后台自动执行 Skill，避免模型漏调用工具导致资料未整理。Function Calling 加入同一队列，等待已接收发言的结果；不会把模型重新描述的事实当作用户发言，也不会因同一发言的工具请求重复生成或扣费。

两个语音工具均为无参数工具，租户、人物、章节、会话和事实来源由服务端绑定。额外事实、人物 ID、未知工具名和无效 JSON 被拒绝。最多接收每事件 8 个调用、每连接 128 个不同调用 ID；相同 `call_id` 和参数复用结果，改变参数重用 ID 则拒绝。批量参数先整体校验再入队。

## 调度与保存语义

- 合并短时间内的连续发言，每批最多 8 条、空闲等待 250ms；工具请求作为有序屏障。
- 记忆按发言顺序处理，剧本在信息充分时更新；纯改稿请求复用已有记忆，不重复执行图谱整理。
- 处理中收到新发言，旧批次可以完成记忆整理，但过时剧本在提交前被拒绝；后续批次继续更新。通话内创作要求在有界内存中保留，避免延后生成时丢失要求。
- 剧本生成前后核对来源指纹，检测到期间新增、更改或审核状态变化则拒绝旧稿，并释放未完成的业务预留扣费。供应商已执行的推理仍可能产生实际成本，不等于供应商退款。
- 只有实际完成才回传 `completed`；没有变化为 `unchanged`；新发言尚待处理为 `pending`；更新失败为 `failed`；非法调用为 `rejected`。
- 页面在仍有后续发言待处理时显示“正在处理后续讲述…”，不提前宣布全部同步。
- 音频收发、打断和心跳不等待后台模型推理。断开时完成本地排队保存，已关闭的供应商连接不再接收工具回传。
- 原始语音、完整对话转写、工具参数不写入持久任务或数据库；仅保留派生记忆。进程异常退出时内存中尚未处理的发言仍可能丢失，本轮没有改变这一隐私取舍，也没有实现跨实例语音任务恢复。

## 记忆更正契约

图谱模型新增 `corrections` 输出，引用旧、新时间线事件的数组下标，提供新来源中的明确更正原句及要关闭的具体冲突键。程序验证来源存在、讲述顺序、同章节、更正引文和日期一致性，拒绝模糊表达。仅移除被取代的事件，保留同一来源中的其他事件和原始记忆，指定冲突标为 `resolved`；未指定的冲突保持原状态。

已有冲突键和状态提供给后续图谱整理；旧冲突记录不再通过整表替换丢弃。图谱输入不再静默只取最后 40 条，而是检查输入预算，超限明确失败。私密和争议记忆不进入真实图谱/传记模型输入。

这一契约约束模型提出的更正操作；模型是否正确识别所有自然语言更正，仍需真实模型样本验收。它不会按关键词直接替换全部人物事实，也不会自动修复历史数据库。

## 内容质量与测试边界

剧本和视频规划提示已补充：未知性别不得从姓名或职业猜测；不露脸要求应覆盖分镜和连续性描述。这是生成约束加强，尚不是对成片逐帧检查的保障，不能据此宣称“生成式面孔”问题已经彻底解决。

本轮验证使用隔离数据库与 mock 供应商，覆盖协议声明/事件路由/批量结果、工具重放、错误参数和租户范围、失败不报成功、连续发言合并、过时剧本拒绝、更正事件与冲突、语音不阻塞音频、Web 同步状态。没有发起付费实时语音或视频调用。

数据库表结构未变化，无新增迁移。本轮只修改本地代码；部署与真实豆包通话验收应分别记录，不能用 mock 协议测试替代真实服务验收。
